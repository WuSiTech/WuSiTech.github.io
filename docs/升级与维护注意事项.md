# 升级与维护注意事项

记录这个站点里"一旦改动/升级就容易踩"的点。日常只需要看第一节的三条命令。

## 平时怎么自检

```bash
# 1) 本地构建 + 产物校验（断链断图、会真正请求的外部资源、sitemap 完整性）
hugo --minify && python tools/check_site.py

# 2) 工具自测（Twikoo 自检工具的 mock 测试 + vendor 是否回退外部 CDN）
python tools/test_check_twikoo.py
python tools/localize_vendor.py --dry-run --strict

# 3) 后台登录中转的自测
node tools/cms-oauth-worker/test.mjs
```

这些也正是 CI 里 [.github/workflows/tools.yml](../.github/workflows/tools.yml) 三个作业跑的东西，
推送后会自动检查，不用每次手动跑。

## 主题（reimu）升级

主题是 git submodule：`git submodule update --remote themes/reimu`，然后**必须做**下面三件事：

1. **重新本地化 vendor 库**。`data/vendor.yml` 是主题那份的**整文件副本**
   （Hugo 对 data 文件不做深合并），主题升级后要重新复制主题的 `data/vendor.yml`，
   再把自己的改动合回去（目前只有 `twikoo` 指向本地 2.0.15），然后跑：

   ```bash
   cp themes/reimu/data/vendor.yml data/vendor.yml   # 重新复制
   # 把 twikoo 那行改回：src: local|twikoo@2.0.15/dist/twikoo.min.js
   python tools/localize_vendor.py                   # 其余库一键本地化
   python tools/localize_vendor.py --dry-run --strict # 确认没有库回退到外部 CDN
   ```

   主题新版本如果换了库的版本号，本地副本目录名要跟着改（脚本会列出缺本地文件的条目）。

2. **确认评论相关配置键名没变**：`config/_default/params.yml` 里的
   `comment.default`、`twikoo.enable`、`twikoo.envId`、`twikoo.region`。
   主题改键名的话评论区会静默消失，改完打开一篇文章页面确认能加载。

3. **确认首页分类卡片还在**：`home_categories.enable` / `home_categories.content`。
   分类名必须小写后能匹配到真实分类（Hugo 的 taxonomy）。

## 构建告警逐条说明

目前每次构建会看到 4 条 WARN，都不影响现在的站点，但要知道含义：

| 告警 | 含义 | 要不要处理 |
| --- | --- | --- |
| `found no layout file for "html" for kind "section"` | `content/posts/` 这个 section 根没有对应模板，所以 `public/posts/index.html` 不产出；但 Hugo 仍把它写进 `sitemap.xml`（线上 `/posts/` 实测返回 200，不影响收录）| 不用。真要让它渲染，加 `layouts/_default/section.html` 即可；注意别加 `content/posts/_index.md`（只会多一条同样的告警）|
| `data from 'covers.yml' overridden by higher precedence` | 站点 `data/covers.yml` 覆盖了主题那份（这是**故意**的：主题默认指向 `d-sketon.top` 外链）| 不用 |
| `data from 'friends.yml' overridden by higher precedence` | 同上，站点 `data/friends.yml` 覆盖主题的示例数据 | 不用 |
| `deprecated: css.Sass: libsass was deprecated ...` | **主题**模板里用的是 libsass，Hugo 计划移除 | **要留意**：等到你升级 Hugo 版本时，如果主题还没切到 dartsass，构建会失败。升级 Hugo 时先看主题更新日志有没有"dart sass"相关提交 |

## 版本要配套

| 组件 | 当前 | 说明 |
| --- | --- | --- |
| Hugo | CI 与 Cloudflare 都用 **0.166.0**（extended）| 本地装的可能是更新版本；改动构建命令时三处要一起改：`.github/workflows/hugo.yaml`、`tools.yml`、Cloudflare 的构建命令 |
| Dart Sass | 1.104.0 | 主题编译 SCSS 需要；CI 两个工作流都会装 |
| Twikoo 前端 | `static/resources/twikoo@2.0.15/` | 必须与后端版本大致匹配；升级见下 |
| Sveltia CMS | `static/admin/sveltia-cms.js`（0.241.0）| 自托管，升级就是重新下载覆盖 |

## 评论后端升级（Twikoo）

前端在仓库里、后端在 Netlify 上，两边版本要大致匹配：

1. 下载新版前端到新目录：`https://registry.npmmirror.com/twikoo/<版本>/files/dist/twikoo.min.js`
   → 放到 `static/resources/twikoo@<版本>/dist/twikoo.min.js`
   （简体中文是内置默认语言，不需要 locales 分片；`twikoo.min.js` 不含腾讯云 SDK，Netlify 用这个）
2. 改 `data/vendor.yml` 的 twikoo 那行路径
3. 后端：Netlify 后台对 `twikoo-netlify` 重新部署即可（它跟随 npm 上的 latest）

## 后台（Sveltia CMS）维护

- 升级：下载 `https://unpkg.com/@sveltia/cms@<版本>/dist/sveltia-cms.js` 覆盖 `static/admin/sveltia-cms.js`
- 加字段：改 `static/admin/config.yml` 的 `fields`；注意文章用 `format: toml-frontmatter`、
  页面用 `yaml-frontmatter`，**这两个值写错会导致新建的文件存成 YAML front matter**
- 站点级配置（`params.yml`：菜单、首页分类、主题参数）**没有放进后台**，
  因为 CMS 保存会按表单字段重写整个文件、丢掉未声明项；要改请直接编辑
  https://github.com/WuSiTech/WuSiTech.github.io/edit/main/config/_default/params.yml
- 登录中转 Worker（`tools/cms-oauth-worker/worker.js`）改完代码要在 Cloudflare 上重新粘贴部署；
  它不存任何数据（HMAC 签名 state + 用户名白名单，无数据库）

## 已知的按需事项

- **live2d 看板娘**（默认关闭）：开启后资源会去 `fastly.jsdelivr.net` 与 `fghrsh/live2d_api`，
  国内可能不通；完整本地化要拖进几 MB 模型文件。要开的话单独处理。
- **图片压缩**：后台上传的图是原图。需要压成 webp 时用
  `python tools/img2webp.py 图片路径 --max-dim 1600 -q 80`（详见该脚本 `--help`）。
