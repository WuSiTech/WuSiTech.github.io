# 站点定制说明（给未来的自己看的地图）

> 一句话：**所有定制都在站点级的 `layouts/`、`static/`、`data/`、`config/`、`functions/` 里，绝不动 `themes/reimu/`**
> （主题是 git submodule，升级时直接 `git pull` 即可；站点文件通过 Hugo 的「站点级覆盖主题」机制生效）。
>
> 这份文档解决一个问题：半年后再来看，能快速知道「这个文件是干嘛的、为什么改、主题升级会不会把它冲掉」。

## 0. 速查：想改什么去哪里

| 想改… | 去这里 |
| --- | --- |
| 页脚 / 页底通栏 / 头部标题去框与字色 / 代码块配色 / 隐藏 RSS 按钮 | `static/css/wusi-site.css`、`static/css/wusi-head.css` |

| 正文图片放大（灯箱） | `layouts/_default/_markup/render-image.html`（相册锚点 + 原图尺寸）+ `layouts/partials/afterFooter.html`（PhotoSwipe 行为选项） |
| 站内搜索前端 | `static/js/search.js`（索引由 `layouts/index.json` 生成） |
| 评论前端 / 评论管理页 | `static/js/comments.js`、`static/comments/admin.html`（详见 [评论系统（Git存储）.md](评论系统（Git存储）.md)） |
| 后台（Sveltia CMS）字段 / 封面下拉框 | `static/admin/config.yml`（**只能改标记区和评论相关字段**） |
| 页脚布局、侧栏 widgets 显示条件、`<head>` 附加内容 | `layouts/partials/` |
| 封面池 / 远端背景源 / 友链 / 厂商库声明 | `data/*.yml` |
| 站点参数（菜单、首页分类卡片等） | `config/_default/params.toml`（其余在 `params.yml`） |
| Cloudflare Function（评论读写、管理接口） | `functions/api/comment.js`、`functions/api/admin.js` |
| 后台 OAuth 中转 | `tools/cms-oauth-worker/worker.js` |
| 打包/媒体 / 校验脚本 | `tools/`、`.github/scripts/`、`.github/workflows/` |

## 1. 文件 → 覆盖了主题的什么 → 为什么 → 主题升级时要注意什么

### 1.1 模板（`layouts/`）

| 文件 | 覆盖/补了什么 | 为什么 | 主题升级时 |
| --- | --- | --- | --- |
| `layouts/partials/footer.html` | 主题 `layouts/partials/footer.html` | 把页脚（虚线+版权+字数）、域名提示、`BLOG状态` 徽章**一起**包进页面最底部整条通栏 `#wusi-footer-bar`（不是 fixed、不是圆角卡片） | 对照主题新版页脚结构重新合并；`#wusi-footer-bar` 的样式在 `static/css/wusi-site.css` |
| `layouts/partials/sidebar.html` | 主题 `layouts/partials/sidebar.html` | 去掉「只有非文章页才渲染 widgets」那个条件，让文章页也显示分类/标签云/最新文章（其余逐行一致，只差这一处） | 重新对照，把那行条件再去掉一次 |
| `layouts/partials/head/init.html` | 主题 `layouts/partials/head/init.html` | 把背景系统数据（当前页 banner、远端图源、本地兜底图）注入 `window.__WUSI_BG__`；保留主题的 Hugo 版本告警 | 主题升级后重新合并，别丢 `window.__WUSI_BG__` 注入 |
| `layouts/partials/head.html` | 主题 `layouts/partials/head.html`（**整份拷贝**） | 唯一改动：iconfont 的 preload 从 `//at.alicdn.com/...` 改成站内 `/resources/iconfont/...`（本站运行期不请求外站） | **每次主题升级都要重新 diff**：`git diff --no-index themes/reimu/layouts/partials/head.html layouts/partials/head.html`，把主题新改动合并进来，只保留 iconfont 那一处不同 |
| `layouts/_default/_markup/render-image.html` | Hugo 的图片渲染钩子（主题自带的是不加钩子的默认输出） | ① 图片路径归一化（去掉 `static/` 前缀、相对路径补根、`%20` 转义、外链原样）—— Obsidian/老文章写法不同也不会断图；② 把 `<img>` 包进 `<a class="article-gallery-item" href="原图">`，主题的 PhotoSwipe 靠这个类名当相册；③ `<img onload>` 把原图 `naturalWidth/naturalHeight` 写进父级 `a` 的 `data-pswp-width/data-pswp-height`（PhotoSwipe 只从这两个 dataset 读尺寸，没有就当 0×0 → 不能缩放） | 若新主题也提供同名钩子，两版合并；**类名不能改**（主题 `afterFooter.html` 里写死了）；`onload` 那一段别丢，否则灯箱只能看不能缩放 |
| `layouts/partials/afterFooter.html` | 主题 `layouts/partials/afterFooter.html`（**整份拷贝**，只多 8 行） | 主题 `initPswp()` 里的 `new PhotoSwipeLightbox({...})` 只传了 `gallery/children/pswpModule`，没配行为选项：默认不能滚轮缩放、竖向拖动会把灯箱关掉。这里补 `bgOpacity: 0.92`、`wheelToZoom: true`、`maxZoomLevel: 4`、`closeOnVerticalDrag: false`、`imageClickAction/tapAction/doubleTapAction: 'zoom'`、`showHideAnimationType: 'zoom'`，**其余逐行一致** | **每次主题升级都要重新 diff**：`git diff --no-index themes/reimu/layouts/partials/afterFooter.html layouts/partials/afterFooter.html`，把主题新改动合并进来，只保留这 8 行不同 |
| `layouts/posts/section.html` | 补齐主题缺失的通用 section 模板 | 主题只给 archives 写了 section，`/posts/` 栏目页会「找不到布局」；这里复用主题的 `partials/post.html` + `pagination.html` 拼一个列表页 | 主题如果补上了 `layouts/posts/section.html`，可删掉这份 |
| `layouts/shortcodes/friendsLink.html` | 主题 `layouts/shortcodes/friendsLink.html` | 后台只填 `example.com`（没写协议）时自动补 `https://`，避免被浏览器当成站内相对路径 | 与主题新版对照合并 |
| `layouts/index.json` | 新增输出格式 | 站内搜索索引 `/index.json`（标题/链接/摘要/标签/日期） | 与 `static/js/search.js` 的字段约定要一起改 |
| `layouts/robots.txt` | 无 | 允许抓取 + 声明 sitemap | 无 |

## 2. 背景系统（一句话版）

- 入口：`layouts/partials/head/init.html` 注入 `window.__WUSI_BG__ = {banner, remote[], local[]}`；`static/js/wusi-bg.js`（defer）负责选图、单请求 `<img>` 铺层、本地兜底、远端 4s 超时/404 记忆（localStorage）、最近 8 张避免重复、标题取色（复用正在显示的图，canvas 采样）。
- 样式：`static/css/wusi-bg.css`，在 `injector.head_end` 引入；另有「头部标题 / 页脚通栏」的样式在 `static/css/wusi-site.css`。
- 数据：远端 `data/remote_backgrounds.yml`；本地 `static/images/pool/bg/`（构建时列目录，10 张，来自 media 分支）。
- 完整细节（调试参数、历史踩坑、验证方式）见 [随机固定背景.md](随机固定背景.md)。

## 3. 正文图片钩子（路径归一化 + 灯箱）

`layouts/_default/_markup/render-image.html` 是所有 Markdown `![](...)` 的唯一出口：

1. **路径归一化**：外链（`http://` `https://` `//` `data:`）原样保留；其余先 URL 解码，再去掉前导 `/`、`../`，然后
   - 含 `static/` → 从 `static` 之后截成站内路径（Obsidian 的 `static/images/obsidian/x.png` 写法）；
   - 否则按 `static/<路径>`、`static/images/obsidian/<路径>` 找真实文件，命中哪个用哪个；
   - 最后把空格转回 `%20`。
2. **灯箱**：输出 `<a class="article-gallery-item" href="原图"><img ... loading="lazy" decoding="async" onload="...data-pswp-width/height..."></a>`。
   主题 `afterFooter.html` 里的 PhotoSwipe 就是找 `.article-entry a.article-gallery-item` 当相册，点击弹层放大。
   - `onload` 把原图 `naturalWidth/naturalHeight` 写进父级 `<a>` 的 `data-pswp-width` / `data-pswp-height`。
     PhotoSwipe Lightbox **只从这两个 dataset 读原图尺寸**（没有就按 0×0 处理 → 所有缩放级别都是 1、
     `isZoomable()` 为 false，滚轮/点击/拖动全都没反应）；主题自带 gallery 短代码也是这么干的。
   - 行为参数在站点级 `layouts/partials/afterFooter.html`：`wheelToZoom: true`（滚轮缩放）、
     `maxZoomLevel: 4`（最大 4 倍）、`closeOnVerticalDrag: false`（按住往下拖不会关灯箱）、
     `bgOpacity: 0.92`、`imageClickAction/tapAction/doubleTapAction: 'zoom'`、`showHideAnimationType: 'zoom'`。
     ⚠️ 这些是站点级覆盖，主题升级要重新 diff（见 10.5）。
   - 关闭灯箱：右上角 ×、点背景、或按 Esc（`bgClickAction` 默认 `close`、`escKey` 默认开）。
3. 历史遗留：`params.yml` 里还留着 Fancybox 的 CSS/JS 与初始化（`static/js/wusi-site.js` 第 1 段），但页面里已经没有 `[data-fancybox]` 元素，那一段是**空转**；真正干活的是主题自带的 PhotoSwipe。保留是为了不引入行为变化，等确认没人用再删。

## 4. 评论系统（数据在 Git 里）

- 前端：`static/js/comments.js`（v15），由 `static/js/wusi-site.js` 按页加载（不是全站加载）。
- 读取：从 `https://wstk.pages.dev/comments/<slug>.json` 读（同域时走同域），失败再回退；跨域由 `static/_headers` 放行。
- 写入：`POST /api/comment` → `functions/api/comment.js` → GitHub Contents API 提交 JSON。
- 管理：`https://wstk.pages.dev/comments/admin.html` → `functions/api/admin.js`（`ADMIN_TOKEN` 保护，支持列表/放行/隐藏/删除/博主回复/令牌体检）。
- 格式：`static/comments/posts/<slug>.json`，每条评论固定 10 个字段，`replyTo` 是嵌套父指针（见 `static/comments/README.md`）。
- 完整部署/排障见 [评论系统（Git存储）.md](评论系统（Git存储）.md)。

## 5. 后台 OAuth 中转（Sveltia CMS 登录）

## 6. media 分支图片池

- `main` 只放**清单**（`data/covers.yml`、`media.lock`），图片本体（374 张封面原图 + 10 张背景兜底）在 `media` 孤儿分支。
- 构建时 `.github/workflows/hugo.yaml` / `tools.yml` 按 `media.lock` 的哈希拉取（`actions/cache` 命中时不额外花时间）到 `static/images/pool/`（已 gitignore）。
- 本地构建前先 `python tools/fetch_media_pool.py`（国内加 `--proxy http://127.0.0.1:7890`），否则封面/背景会 404（`check_site.py` 会报断链）。
- 加图：把原图提交到 media 分支 `images/pool/covers/` → `sync-cover-pool.yml` 自动更新 `data/covers.yml` + 后台 `COVER_OPTIONS` 标记区并触发一次部署。
- 细节见 [图片池（media 分支）.md](图片池（media%20分支）.md)。

## 7. Obsidian 写作流

- Obsidian 配置（`.obsidian/`）是仓库的一部分：图片粘贴默认落到 `static/images/obsidian/`（`attachmentFolderPath`），链接用绝对路径（`newLinkFormat: absolute`），这类写法由第 3 节的图片钩子兜住。
- 模板：`_templates/文章.md`（Obsidian 模板插件插入 front matter）。
- 推送：`docs/obsidian-push.bat`（Windows 一键 `git add` 指定文件 + commit + push），以及 `.obsidian` 里的 obsidian-git 插件配置。
- 写作说明见 [Obsidian写作.md](Obsidian写作.md)；未命名笔记（`content/posts/未命名.md`、`Untitled.md`）已在 `.gitignore` 里，不会误发布。

## 8. 配置分工（`config/_default/`）

| 文件 | 管什么 | 谁在改 |
| --- | --- | --- |
| `hugo.yml` | `baseURL` / `title` / `theme` / `mainSections` / `enableRobotsTXT` / 代码高亮 / `cascade: params.banner: false`（关掉主题默认 banner）/ 首页额外输出 `index.json` | 手动 |
| `params.yml` | 主题主配置（`injector`、`widgets`、`comment`、`footer`、`sidebar`、`subtitle` 等）。**`injector` 里现在只有 `<link>` / `<script src>` 引用，没有内联 `<style>` 和业务 `<script>`**（2026-10 重构时拆到 `static/css|js/wusi-*`） | 手动；**刻意不放后台**（CMS 保存会按表单字段重写整个文件，没声明的键会被丢掉） |
| `params.toml` | 作者信息、`[[menu]]`、`home_categories`（首页分类卡片） | 后台「站点设置」集合 |
| 仓库根 `hugo.toml` | 与 `config/_default/hugo.yml` 重复的历史遗留；有 `config/` 目录时 Hugo **只读 `config/_default/`** | 没人改，留着不影响 |

后台「站点文案」集合写 `i18n/zh-CN.yml`（导航文字）；后台「评论」集合写 `static/comments/posts/*.json`。

## 9. 运行期还会发起的「外站请求」（有意保留的）

`tools/check_site.py` 的硬约束是「运行时不依赖被墙的外部 **JS/CSS/字体**」；以下几类是有意保留、且有兜底的：

| 请求 | 兜底 | 说明 |
| --- | --- | --- |
| GitHub Actions 徽章 SVG（`github.com`） | 页面里同时引用本地镜像 `static/badges/*.svg` | 页脚 `BLOG状态` 只引用本地镜像，不请求外站；README 里才用 GitHub 地址 |
