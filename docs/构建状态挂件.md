# 页底「BLOG状态」固定条

页面最底部那条深色小条：左边一行小字「BLOG状态」，右边两张 GitHub Actions
徽章（`Build and deploy`、`Tools and config checks`）。点徽章跳到对应的 Actions 页面。

它替代了以前「自己查 GitHub API → 写 `data/build_status.yml` → 渲染
`/build-status.json` → 前端 JS 填字」那一整套（那套经常显示「未知」），
现在**状态就写在徽章 SVG 里**，由 GitHub 自己算。

## 一、两张徽章是本地文件

页面引用的是站内路径，**运行时一个外部请求都不发**（`tools/check_site.py`
的「会真正请求的外部资源」必须为 0）：

| 页面引用 | 仓库文件 | 来源 |
| -------- | -------- | ---- |
| `/badges/build-and-deploy.svg` | `static/badges/build-and-deploy.svg` | `https://github.com/WuSiTech/WuSiTech.github.io/actions/workflows/hugo.yaml/badge.svg?branch=main` |
| `/badges/tools-and-config-checks.svg` | `static/badges/tools-and-config-checks.svg` | `https://github.com/WuSiTech/WuSiTech.github.io/actions/workflows/tools.yml/badge.svg?branch=main` |

这两个地址就是 `README.md` 顶部那两张徽章的地址；仓库里的 SVG 是**原样镜像**
（不改内容），所以页面上看到的图和 README / GitHub 上的完全一致。

### 谁去更新它们

- `.github/scripts/fetch_badges.py`：只用标准库 `urllib`，把上面两个地址下载到
  `static/badges/`。写文件是「先写临时文件再 `os.replace`」，不会留半截文件。
- `.github/workflows/hugo.yaml` 里在 `hugo` **之前**跑它（步骤 `Mirror workflow badges`）。
- **失败不阻塞构建**：没网 / 限流 / 拿到的不是 SVG / 写盘失败，都只打一条
  `::warning::` 然后保留仓库里已有的那份，脚本**永远 exit 0**；CI 步骤另外还有
  `continue-on-error: true` 兜底。仓库里提交的首份副本就是兜底文件。
- 徽章是公开端点，不带 token 也能取；脚本默认读 `GITHUB_TOKEN`，带了反而 401/403
  会自动退回匿名重试。
- 本机想手动刷新（走代理）：

  ```bash
  python .github/scripts/fetch_badges.py --proxy http://127.0.0.1:7890
  ```

### 工作流改名 / 换文件时必须同步

- `.github/scripts/fetch_badges.py` 里的 `BADGES` 地址表；
- `layouts/partials/footer.html` 里两个 `<a href>`（徽章块；2026-10 重构后不再写在 `params.yml` 的 injector 里）；
- `README.md` 顶部的徽章链接。

## 二、位置：页面最底部那条通栏里的一行

徽章块在 `layouts/partials/footer.html` 里、页脚之后的 `.wusi-badges`，现在被包进
`<div id="wusi-footer-bar">`，也就是**页面最底部的整条通栏**里（见
[随机固定背景.md](随机固定背景.md) 的「页脚：页面最底部的整条通栏」一节）：

- 通栏是满宽、无圆角的（背景半透明 + 毛玻璃），抬头是主题的虚线 `.footer-line`；
  它在**正常文档流**里，是页面的最后一块内容，**不固定、不悬浮**在视口上；
- 徽章在通栏里只是**透明、满宽、居中**的一行（`.wusi-badges` 用 flex 居中），
  和页脚版权、域名提示一起由这一整条的背景承载，不再自己带卡片背景；
- 主题右下角的圆形按钮 `.sidebar-top`（`position: fixed; bottom: 30px; 48×48; z-index: 999`）
  保持默认位置，滚到页面最后时浮在通栏右侧上方。

## 三、删掉的旧链路

以下文件与用法**已整条删除**（`/build-status.json` 不再生成）：

| 文件 | 原来的作用 |
| ---- | ---------- |
| `content/buildstatus.md` | 触发 `/build-status.json` 生成的假页面 |
| `layouts/_default/single.buildstatus.json` | JSON 输出模板 |
| `layouts/partials/build_status_row.html` | 状态 → 文案/配色的映射 |
| `data/build_status.yml` | 构建期写入的状态数据 |
| `static/js/build-status.js` | 前端 fetch JSON 填字 + 窄屏展开收起 |
| `tools/check_build_status.py` | 校验上面那套产物的工具 |
| `.github/scripts/write_build_status.py`、`.github/scripts/test_write_build_status.py` | CI 里查 GitHub API 写状态数据 + 它的 mock 测试 |
| `config/_default/hugo.yml` 里的 `mediaTypes` / `outputFormats.buildstatus` | JSON 输出格式 |
| `config/_default/params.yml` 里旧的 `.build-status` 自绘胶囊外壳 | 旧挂件本体 |

CI 侧同步清理：`hugo.yaml` 去掉了 `Collect build status` 与部署失败时「补发
build-status.json」的三步（也去掉了不再需要的 `actions: read`），
`tools.yml` 里的语法检查改成自动收集全部 Python 文件，不再点名已删除的脚本。

**保留 `write_build_status.py` 也没有意义**：它唯一的用途就是喂
`/build-status.json`；删掉后 CI 反而更简单（不再需要 `actions: read` 权限）。

## 四、本地怎么验证

```bash
# 1) 用代理刷新徽章（可选，仓库里已有兜底副本）
python .github/scripts/fetch_badges.py --proxy http://127.0.0.1:7890

# 2) 构建
hugo --minify --destination .verify-b3/out --baseURL https://wusitech.github.io/

# 3) 产物检查（必须 ALL PASS，且「会真正请求的外部资源」= 0）
python tools/check_site.py --dir .verify-b3/out

# 4) 产物里应当有 badges/*.svg，且首页/文章页引用的是 /badges/... 本地路径
ls .verify-b3/out/badges
```

目视检查（可选）：起个静态服务器（`python -m http.server --directory .verify-b3/out 8731`）
后用无头浏览器截图桌面 1280×900、手机 390×844，确认固定条贴在视口底部、
不压住圆钮、页脚内容没被遮住。

## 五、改这个挂件时容易踩的坑

- **不要**把 `<img src>` 写回 `https://github.com/...`：`tools/check_site.py`
  会把「会真正请求的外部资源」判为 FAIL（本站硬约束）。
- 徽章 SVG 要保持**原样**（含 `<title>` 与 GitHub 那个小圆标图标），
  才和 README 一模一样；不要为了「好看」去改它。
- 固定条高度变了要同步改 `body { padding-bottom }`，否则会盖住页脚。
- 小字标题在窄屏是**独占一行**（`flex: 0 0 100%`），两张徽章缩到 0.8 放下一行；
  改宽度时记得在 390px 上量一下条右边缘是否还在圆钮左边。
