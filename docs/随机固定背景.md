# 随机固定背景（全站）

> 一句话：全站背景是一张 **不随页面滚动** 的大图。文章页显式写了 `banner` 就用它；否则从远端图源随机取一张，
> 远端图没来/失败就立刻用本地图池的图兜底。整条链路只有一次图片请求，不阻塞首屏。

## 目标

1. 背景是一张 **`position: fixed`** 的大图（`#wusi-bg` 铺满视口，不随滚动）；
2. 非文章页（首页 / 关于 / 友链 / 下载 / 分类 / 标签…）从 `data/remote_backgrounds.yml` 的远端图源里**随机**取一张；
3. 文章页：**只有 front matter 里显式写了 `banner`** 才用它当整屏背景；
   没写 banner 的文章（不管有没有 `cover`）和普通页面一样走随机图源 —— `cover` 只是首页卡片缩略图，**不参与**背景；
4. **脚本一开始就铺本地兜底图**，远端图加载好后再淡入覆盖；远端失败/超时（4s）就保留本地图，不会先闪一下纯色底；
5. 远端图 404 会记进 `localStorage`，7 天内不再选它；最近用过的图（远端 8 张 / 本地 4 张）也尽量避开；
6. 背景不拖慢首屏、不产生横向滚动条、不遮挡内容。

## 文件

| 文件 | 作用 |
| --- | --- |
| `layouts/partials/head/init.html` | **站点级覆盖**主题同名 partial（不改 `themes/`）：构建时把 `banner` / `remote[]` / `local[]` 注入成 `window.__WUSI_BG__`（约 10KB JSON，gzip 后 ~3KB，不发请求）；有 banner 的页面在 `<head>` 里就加上 `wusi-page-banner` 类 |
| `static/css/wusi-bg.css` | 背景层样式（`#wusi-bg` 固定定位 / `<img>` 层铺满 / 亮暗遮罩）；放开主题 `html/body/#wrap/#container` 的不透明底色；内容卡片半透明+毛玻璃；有 banner 的页面把主题的 `#header img` 改成整屏固定背景；文件末尾是「点击背景查看大图」的查看层样式 |
| `static/js/wusi-bg.js` | 选图、单请求 `<img>` 铺层、淡入、失败回落、坏图记忆、状态上报（`window.__wusiBg`）；文件后半部分还有**页头悬停淡出**、**头部标题文字取色**和**点击背景查看当前大图**（查看层逻辑在文件最末尾） |
| `static/css/wusi-site.css` | 头部标题去框/自适应字色、页脚通栏 `#wusi-footer-bar` 的样式（2026-10 重构时从 `params.yml` 内联样式拆出来的，用 `injector.body_end` 引入，位置不变） |
| `config/_default/hugo.yml` | `cascade: params.banner: false`：关掉「没写 banner 就渲染站点默认 banner.webp」的老行为，省掉一次 155KB 的无用图片请求 |
| `config/_default/params.yml` | `injector.head_end` 引 `/css/wusi-bg.css`、`injector.body_end` 引 `/js/wusi-bg.js`；副标题打字开关（`subtitle.typing`） |
| `layouts/partials/footer.html` | 站点级覆盖主题页脚：把 `#footer`、域名提示、`BLOG状态` 徽章一起包进页面最底部的整条通栏 `#wusi-footer-bar` |

数据来源（都不用手改代码）：

- 远端图源：`data/remote_backgrounds.yml` 的 `remote_backgrounds` 列表（**当前 98 条**，全部 HEAD 校验 200）；
- 本地兜底：构建时用 `os.ReadDir "static/images/pool/bg"` 直接列目录，往这个目录加 `.webp` 就会自动进兜底池（不用改配置）。
  图片本体在 `media` 孤分支，构建时由工作流拉到该目录（本地构建前先跑 `python tools/fetch_media_pool.py`），
  详见 [图片池（media 分支）.md](图片池（media%20分支）.md)。

## 工作流程（现行实现）

```
页面加载
  └─ <head>: window.__WUSI_BG__ = {banner, remote[...], local[...]}      （只注入数据，不发请求）
  └─ /js/wusi-bg.js（defer）执行：
       ├─ ① 立刻建 #wusi-bg 层、选一张本地图加载（showFallback）——首屏马上有图，不等远端
       ├─ ② 本页有 banner → 不下载新图：等主题 #header 里那张 banner <img> load 完
       │       （naturalWidth > 0 才算成功）→ settle("banner")；失败则撤掉整屏类名、藏掉坏图 → 走 ③
       └─ ③ 本页没有 banner → 从 remote 里挑一张（排除 localStorage 坏图 + 本次已试 + 最近 8 张）
               ├─ 用 <img> 发一次请求（远端图优先 crossOrigin=anonymous，为了后面 canvas 取色）
               ├─ onload → 放进上层 #wusi-bg img，淡入（0.8s）覆盖本地兜底 → settle("remote")
               ├─ 对方没给 CORS 头 → 换普通 <img> 再加载一次（保证背景一定能显示；这是唯一会多一次请求的路径）
               ├─ onerror → 记进 wusi_bg_bad_v1（7 天），换一张重试（自动模式最多 2 张）
               └─ 4s 超时 → 放弃远端，保留本地兜底 → settle("local")
```

时间/数量参数都在 `static/js/wusi-bg.js` 顶部：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `REMOTE_TIMEOUT` | 4000 ms | 远端图超时 |
| `REMOTE_AUTO_TRIES` | 2 | 自动模式下最多试几张远端图 |
| `BAD_KEY` / `BAD_TTL` | `wusi_bg_bad_v1` / 7 天 | 远端坏图记忆（localStorage，最多留 40 条） |
| `HIST_REMOTE_KEY` / `HIST_REMOTE_SIZE` | `wusi_bg_hist_remote` / 8 | 最近用过的远端图（sessionStorage，避免连着撞同一张） |
| `HIST_LOCAL_KEY` / `HIST_LOCAL_SIZE` | `wusi_bg_hist_local` / 4 | 最近用过的本地兜底图 |

### 调试参数（正常访问不会带）

| URL | 效果 |
| --- | --- |
| `?wusi_bg=local` | 跳过远端，直接本地兜底 |
| `?wusi_bg=remote` | 强制走远端随机（只试 1 张） |
| `?wusi_bg=fail` | 故意让远端失败（走真实 `onerror` 路径），验证回落 |
| `?bgimg=<url>` | 强制指定一张背景图（验证头部文字颜色、回滚等），如 `?bgimg=/images/pool/bg/12728082_180635373000_2.webp` |

`window.__wusiBg` 是给调试/自动化用的状态对象：
`{settled, visible, source, image, mode, el}` —— `source` 是 `"banner" / "remote" / "local" / "none"`，
`settled: true` 表示最终背景已定下来，`el` 是当前显示在最上层的那个 `<img>`（标题取色直接复用它，不再二次请求）。
`<html>` 上会出现 `wusi-bg-ready`（有图）和 `wusi-page-banner`（本页用 banner）两个类名。

## 关键实现点（踩过的坑）

1. **背景层看不见的根因不是 z-index**，而是主题的两层不透明底色：
   `body { background: var(--color-background) }`、`#wrap { position:absolute; z-index:1; background: ... }`。
   所以 `wusi-bg.css` 把 `html/body/#container/#wrap` 的底色放开，只留 `html` 的底色当「还没图」时的兜底。
2. **不要用 `100vw` 铺满**：`100vw` 含滚动条宽度，会把页面撑出横向滚动条。背景层一律 `position: fixed; inset: 0`，
   banner 图一律 `width: 100%`。
3. **一张图只请求一次**：旧实现先 `new Image()` 探测再设 `background-image`（同一张图下载两遍），
   现在探测和显示是**同一个 `<img>` 元素**（`#wusi-bg img.wusi-bg-layer`），`onload` 后直接淡入；
   CORS 探测顺便给「头部文字颜色采样」复用。
4. **文章页 banner 复用主题已经渲染好的 `#header img`**（`display` 改成 `fixed` 铺满、去掉主题的渐变 mask，
   用 `html.wusi-page-banner` 控制），不再下第二遍同一张图 —— 它本来就是 `fetchpriority=high` 提前加载的。
5. **文章页 banner 是 `<img>` 直接子元素，普通页面的站点 banner 被 `<picture>` 包着**，所以隐藏规则要写
   `#header img` + `#header > picture`，否则首页那张 banner 会露出来。
6. **移动端横向滚动条**：`#header-title` 的 `width: calc(100% - 32px)` 与主题 `width:95%` 叠加时，必须
   `box-sizing: border-box`（样式在 `wusi-site.css`），否则窄屏会超出视口。
7. **暗色模式头部标题看不清**：浅色规则里的 `#header-title #logo h1`（两个 id）优先级高于
   `html[data-theme="dark"] #header-title h1`（一个 id），暗色规则里要补 `#logo` 那一级。
   亮/暗主题的判定看 `data-theme` 属性，用 `MutationObserver` 监听（不要监听 class，会和 JS 加类互相触发）。
8. **面板居中**：`#header-title` 是主题的 `position:absolute; width:95%`，只写 `margin:0 auto` 不生效；
   用 `left:50%; top:50%; transform: translate(-50%,-50%)` 才真居中（主题的 `fade-in-blur` 只动 opacity/filter，不冲突）。
9. **宽度和主内容对齐**：桌面 `#main/#sidebar` 左右各 `margin: 0 16px`、手机是 `#main padding: 0 16px`，
   所以面板/页脚通栏用 `width: calc(100% - 32px); max-width: 1318px`（1318 = `layout.max_width` 1350 − 32）。
   768~959px 无侧栏、`#main` 是 `padding: 0 20px`，单独用媒体查询改成 `calc(100% - 40px)`。
   ⚠️ 改 `params.yml` 的 `layout.max_width` 时要同步改 `static/css/wusi-site.css` 里的 `1318`。
10. **本地兜底第一张也可能挂**：`showFallback()` 在本地图 onerror 时会换下一张（同样是「排除本次已试」），
    全挂才 `settle("none")`，页面只剩主题底色，依然正常。
11. **坏图记忆别无限涨**：`wusi_bg_bad_v1` 只留最近 40 条、7 天过期 —— 同一张坏图不会拖慢以后每次首屏。

## 头部：不用面板，文字颜色跟随背景明暗

- `#header-title` 没有半透明框（`background` / `backdrop-filter` / `padding` / `border-radius` 全去掉了），
  只保留居中与和主内容对齐的宽度（样式在 `static/css/wusi-site.css`）；
- `wusi-bg.js` 用 `<canvas>` **复用当前正在显示的那张背景图**（`window.__wusiBg.el`，远端图是 CORS 方式加载的，
  所以能读像素）采样标题区域的平均亮度：按 `object-fit: cover` 映射回原图，取视口中间 50% 宽、header 垂直中段；
- 算出的亮度再叠加亮色主题那层 12% 白遮罩（`#wusi-bg::after` 的 `rgba(255,255,255,0.12)`）得到等效亮度，
  `> 0.6` → `html.wusi-hero-light`（黑字 `#222` + 浅色阴影），否则 `wusi-hero-dark`（白字 + 深色阴影）；
- 暗色主题：背景有一层 45% 黑遮罩、页面整体深色，统一白字，**不读像素**（也就不用等 CORS）；
- 读不到像素（图没 CORS / 加载失败）就保持默认的「白字 + 深阴影」，不报错；
- 采样时机：`wusi:bg-visible` / `wusi:bg-settled` 事件、`load` 后 200ms、`resize` 防抖 300ms、`DOMContentLoaded` 兜底、
  亮暗主题切换（`data-theme` 变化）。`window.__wusiHeroLum` 能看到当次算出的亮度（0~1）。

## 悬停顶部大图 → 内容淡出（对齐 cialloking 的实现）

`wusi-bg.js` 里绑定 `#header` 的 `mouseenter` / `mouseleave`（只在有精确指针的设备上启用，触屏不绑）：

- 进入 `#header`：`#content` 在 1s 内从 1 线性降到 0.1，再用 2s 从 0.1 降到 0（逐帧改 `opacity`）；
- 移出：立即恢复 1（CSS 有 `#content { transition: opacity .2s ease }`，恢复更柔和）；
- 只影响 `#content`（正文 + 侧栏），页脚通栏、回到顶部按钮不受影响；
- 想调速度改 `wusi-bg.js` 里的 `DURATION1` / `DURATION2` / `MID`。

## 点击背景 → 全屏查看当前这张背景图

- 背景层 `#wusi-bg` 本身是 `pointer-events: none`（不挡页面点击），所以**不能**给它绑 click；
  实现是在 `document` 上做事件委托，只有点中下面这些「空白容器本身」才打开：
  `html` / `body` / `#wrap` / `#container` / `#main` / `#content` / `#sidebar` / `#header` / `#header-outer`
  （`#header-outer` 是主题头图里包着 `#header-title` 的那层，点标题以外的头部空白就是它）。
  点在链接、按钮、输入框、正文、文章卡片、页脚通栏上**不会**触发；正在选文字时也不触发。
- 打开后显示的是当前**真正在用**的那张图：取 `window.__wusiBg.el` 的 `currentSrc` / `src`
  （有 banner 的文章页就是 `#header` 里那张头图），没有 `el` 时退回 `__wusiBg.image`；
  用的就是浏览器已经缓存的那张，不会二次请求。
- 查看层 `#wusi-bg-viewer`（`static/css/wusi-bg.css` 末尾）：全屏深色遮罩 + 图片 `contain` 居中，
  `max-height: calc(100vh - 96px)` 给底部提示留位置；打开时 `html` 加 `wusi-bg-viewing`
  （显示遮罩 + 锁 `html`/`body` 滚动）。**Esc / 点击遮罩空白处 / 右上角 ×** 关闭，关闭后焦点还给原来的元素。
  ⚠️ 点**图片本身**不会关闭（要留给双击缩放 / 拖动平移）。
- **滚轮缩放 + 拖动平移**：滚轮以鼠标位置为锚点缩放（1x ~ **4x**，`MAX_ZOOM` 常量）；
  放大后按住图片可拖动平移（`translate3d` + `scale`，边界按「放大后多出来的部分」夹紧）；
  双击图片在 **1x ↔ 2x** 之间切换、并回到鼠标位置；关闭 / 重新打开会自动复位到 1x。
  每次缩放/平移的计算：`translate` 先于 `scale`，缩放锚点按 `T' = P - ((P - T) * ratio)` 保持鼠标下的像素不动。
  触屏暂未做双指捏合（但触控板双指滚动等同滚轮）。
  ⚠️ 滚轮监听绑在 **`document` 的捕获阶段**（`{capture:true, passive:false}`），不是绑在遮罩上：
  这样查看层打开后滚轮落在图片/遮罩/任何盖在上面的元素上都能收到，也不会被主题或扩展的滚动监听吞掉。
  如果只在遮罩上绑一份、又在 document 上绑一份，一次滚轮会缩放两次（1.2 → 1.44），**不要重复绑定**。
- 事件与调试入口：打开派发 `wusi:bg-viewer-open`（`detail.url`），关闭派发 `wusi:bg-viewer-close`；
  `window.__wusiBgViewer = { open, close, isOpen, getZoom, resetZoom, switchBackground }`
  可以直接在控制台调。
- **版本标记**：`wusi-bg.js` 顶部有 `WUSI_BG_VERSION`，运行时会写 `window.__wusiBgVersion`
  和 `<html data-wusi-bg-version="…">`。排查「改了怎么没生效」时先看这两个值是不是最新版
  （见文末「缓存」一条）。
- **导航栏提示小字**：确认当前页有背景图可看之后，`wusi-bg.js` 会往 `#sub-nav`（搜索图标所在容器）末尾
  插一行 `<span id="wusi-bg-hint">点击背景图可看全图</span>`，12px、博丽灵梦红 `#e60012`
  （可用 CSS 变量 `--wusi-reimu-red` 覆盖；深色主题下透明度略提），≤1024px 隐藏以免挤坏导航。
  没有背景图（`settle("none")`）的页面不会插这行提示，避免「点了没反应」的假提示。
- **换图按钮**：同一处还会插 `<button id="wusi-bg-switch">`（刷新箭头图标，博丽灵梦红），
  点一下 = 调 `window.__wusiBgSwitch()` 换一张随机背景（复用自动选图规则：排除当前图、坏图、
  最近 8 张；加载失败自动换下一张，最多试 3 张）。加载中图标转圈（`is-loading`），
  成功时派发 `wusi:bg-switched`、全失败派发 `wusi:bg-switch-failed`。
  有 banner 的文章页点换图会先撤掉整屏 banner 再换成随机图。
- ⚠️ 改了 `wusi-bg.css` / `wusi-bg.js` 要把 `config/_default/params.yml` 里
  `/css/wusi-bg.css?v=` 与 `/js/wusi-bg.js?v=` 的版本号一起加 1（当前 v=6），
  并把 `wusi-bg.js` 里的 `WUSI_BG_VERSION` 同步改成同一个数字，否则缓存不会更新。

## 页脚：页面最底部的整条通栏（不是圆角卡片，也不固定在视口上）

- `layouts/partials/footer.html` 把 `#footer`（虚线 + 版权 + 字数/阅读时长）、域名提示、`BLOG状态` 徽章
  **一起**包进 `#wusi-footer-bar`；
- `#wusi-footer-bar`：满宽、无圆角、半透明 + `backdrop-filter: blur(14px) saturate(1.05)`，暗色模式换深色半透明；
  它**没有** `position: fixed`，就是正常文档流最后一块，只有滚到页面末尾才看到它；
- 条内三块都只是**透明、满宽、无圆角、无外边距**的「行」，虚线用主题的 `.footer-line`
  （本来就是 `width:200%` + 横向滚动动画）正好横贯整条；
- 样式在 `static/css/wusi-site.css`（`injector.body_end` 引入，必须在主题 CSS 之后）；
- 回到顶部按钮保持主题默认的右下角（`bottom:30px`、`z-index:999`），滚到页面最后时浮在通栏右侧上方。

## 已知事项 / 维护

- 背景层 `pointer-events: none`，不会挡任何点击/选择；层级 `z-index: -1`（在内容之下、html 底色之上）。
  「点击背景看大图」走的是 `document` 上的事件委托，不是给背景层本身绑 click（见上文）。
- 打印时 `#wusi-bg` 隐藏、白底黑字。
- 换封面/头图：文章在后台（Sveltia CMS）改「文章页顶部大图（banner）」即可，保存后下一次构建自动生效；
  留空则该文章用随机背景。
- **缓存（排查「怎么没生效」必看）**：GitHub Pages / Cloudflare 给 HTML 的响应头是
  `Cache-Control: max-age=600`，也就是**部署后最多 10 分钟内，浏览器可能还在用旧 HTML**，
  旧 HTML 引用的是旧的 `wusi-bg.js?v=旧号`，表现就是「新功能没反应」（比如某页面的灯箱不支持滚轮）。
  遇到这种情况先 **Ctrl+F5 强制刷新**；然后到控制台看 `window.__wusiBgVersion`
  （或看 `document.documentElement.dataset.wusiBgVersion` / 页面源码里 `wusi-bg.js?v=` 的数字），
  确认加载到的是不是最新版。不同页面各自缓存，可能出现「首页已更新、文章页还是旧的」。
