# 站内本地搜索（构建期索引，零外部请求）

**主题自带的搜索是 Algolia**（境外 API），本站一直是关的：
`config/_default/params.yml` 的 `algolia_search.enable: false`。
现在站上用的是**自建本地搜索**：索引在 Hugo 构建时生成成一个静态 JSON，
浏览器只在同域取这一个文件，**不请求任何外部资源**（`tools/check_site.py` 会拦外链）。

## 由哪几块组成

| 文件 | 作用 |
| --- | --- |
| `config/_default/hugo.yml` → `outputs.home: [HTML, RSS, JSON]` | 让首页**多输出一个** `/index.json`（Hugo 内置的 JSON 输出格式，`baseName` 就是 `index`） |
| `layouts/index.json` | 索引模板：遍历 `mainSections`（也就是 `content/posts/`）下所有文章，输出 `title / url / summary / tags / date` |
| `static/js/search.js` | 入口按钮 + 覆盖层 + 本地过滤（全部逻辑在这个文件里，CSS 也由它注入） |
| `config/_default/params.yml` → `injector.body_end` | 注入 `<script src="/js/search.js" defer>` |

`/index.json` **不会进 `sitemap.xml`**：它挂在首页的输出格式上，sitemap 里的首页地址仍然是 `/`，
不会多出任何条目（这点已用构建产物核对过）。

## 界面行为

- 入口按钮由脚本在运行时创建，**插进主题 header 的 `#sub-nav`（页面右上角，和主题自己追加的
  暗色模式按钮并排）**；做法和主题 `assets/js/main.ts` 往 `#sub-nav` 追加暗色按钮完全一致。
- 主题如果哪天删掉/改了 `#sub-nav`，脚本会**退回左下角的固定圆钮**，功能不受影响
  （不放右下角，是因为主题「回到顶部」圆钮在那里）。
- 点击入口弹出覆盖层：输入框自动聚焦，输入即实时过滤；结果点标题或回车跳文章。
- 关闭方式：**Esc**、**点遮罩**、面板右上角的 **✕**。
- 无结果时显示「没有找到匹配的文章，换个关键词试试。」；面板配色全部走主题 CSS 变量
  （`--color-wrap` / `--grey-7` / `--grey-9` / `--red-1` / `--red-2`），深色模式自动跟随；
  窄屏（390px 实测）面板宽度 `min(680px, 92vw)`，不出屏。

## 关键词匹配规则（`static/js/search.js` 里的 `score()`）

1. 查询按空格分词，**每个词都必须至少命中一次**（AND 语义），全部命中的条目才有分。
2. 加权：命中**标题 +60**、**标签 +25**、**摘要 +10**；总分降序，最多显示 30 条。
3. 匹配是**子串匹配**（`indexOf`），不做分词、不区分简繁、不支持拼音/同义词。
   - 好处：中文不必装分词库，零依赖；「中断」「STM32」这类词直接就能命中。
   - 代价：单字查询（例如「的」）会命中很多条；英文不区分大小写但不做词形还原。

## 索引里有什么

- **范围**：只索引 `mainSections`（`content/posts/` 下的文章）。`about` / `friend` / `download`
  这类固定页面**不在**索引里 —— 它们是导航页，不是文章。
  想把固定页也搜到：把 `layouts/index.json` 第 1 行的
  `where .Site.RegularPages "Type" "in" .Site.Params.mainSections` 换成 `.Site.RegularPages`。
- **字段**：`title`、`url`（`RelPermalink`，站内相对路径）、`summary`（`.Summary | plainify | truncate 160`）、
  `tags`、`date`。
- **体积**：一篇文章一条记录（摘要 ≤160 字符），当前 3 篇文章的 `/index.json` 约 1.4 KB。
  文章上百篇时索引大约几十 KB —— 仍然是一次同域请求，但要注意别往里塞全文。
- 想**排除某一篇**：在它的 front matter 里写 `no_search: true`（文章用 TOML 就写
  `no_search = true`），`layouts/index.json` 已经会跳过它。

## 为什么不用 lunr / fuse 之类的库

它们要么得从 CDN 拉（本站硬性禁止运行时外部请求），要么得往仓库里塞一个几十 KB 的
minified 副本再在 `data/vendor.yml` 里登记本地化。当前文章量下，二十来行的子串加权匹配
就够用，还少一份需要跟着主题升级同步的 vendor 文件。文章量明显变大（几百篇）再考虑引入。

## 维护与风险

- **`hugo.yml` 的改动会影响两处构建**：GitHub Actions（`.github/workflows/hugo.yaml` / `tools.yml`，
  Hugo 0.166.0）和 Cloudflare Pages。`outputs` 是 Hugo 很老的配置键，两处都支持；
  改完最好推一次让 CI 的「Hugo 构建检查」跑一遍。
- **主题升级**（`git submodule update --remote themes/reimu`）后要确认：
  1. 页面里还有 `#sub-nav`（搜索入口挂在里面；没有就会退回左下角圆钮，功能仍在）；
  2. 主题没有把 `outputs` 或 `layouts/index.json` 的查找顺序改掉 —— 构建后访问 `/index.json`
     能拿到 JSON 即正常。
- **中文分词**：见上文匹配规则，属于已知取舍，不是 bug。
- **自检**：

  ```bash
  hugo --minify --baseURL https://wusitech.github.io/
  python tools/check_site.py --dir public      # 必须 ALL PASS，且「会真正请求的外部资源」= 0
  python -c "import json;d=json.load(open('public/index.json',encoding='utf-8'));print(len(d),d[0])"
  ```
