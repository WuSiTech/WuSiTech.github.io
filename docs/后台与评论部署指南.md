## 一、写作后台（https://wusitech.github.io/admin/）

后台本身**已经可以打开了**（页面、配置、Sveltia 本体都部署好了），只差「登录」。有两条路线，任选其一：

| 路线 | 你要做什么 | 体验 |
| --- | --- | --- |
| **访问令牌（PAT）** | 2 分钟：在 GitHub 建一个只对这个仓库可读写的令牌，粘进后台 | 立刻可用；令牌存在浏览器本地，有有效期，过期重建 |
| **GitHub OAuth（推荐长期用）** | 约 10 分钟：建一个 OAuth App + 部署一个免费 Cloudflare Worker | 以后点一下按钮就登录，不用再管令牌 |

### 路线 A：访问令牌登录（零配置，马上能用）

1. GitHub → 右上头像 → **Settings** → 左侧最下 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
2. **Repository access** 选 `Only select repositories` → 只勾 **`WuSiTech.github.io`**
3. **Permissions** → Repository permissions → 把 **Contents** 设为 **Read and write**（Metadata 会自动带上 Read）
4. **Expiration** 建议 90 天～1 年 → 生成后**立刻复制**令牌（只显示一次）
5. 打开 https://wusitech.github.io/admin/ → 点 **「使用访问令牌登录」** → 粘贴令牌

> 不想用细粒度令牌也可以，经典令牌勾上 `repo` 权限一样能用。
> 令牌相当于该仓库的读写钥匙，别发给别人；过期后重新生成一个即可。

### 路线 B：GitHub 登录中转（推荐，配对一次长期有效）

**建议按这个顺序做，少走回头路**：先部署 Worker 拿到地址 →
再建 OAuth App（callback 直接填 Worker 地址 + `/callback`）→ 回 Worker 填环境变量 →
最后把地址回填到 `static/admin/config.yml`。下面第 1、2 步对调着做即可。

#### 1. 建一个 GitHub OAuth App

打开 https://github.com/settings/applications/new

| 字段 | 填什么 |
| --- | --- |
| Application name | `吾思梦阁后台`（随便）|
| Homepage URL | `https://wusitech.github.io/` |
| Authorization callback URL | `https://<你的Worker名>.<你的Cloudflare子域>.workers.dev/callback` |

> callback 必须先和下一步部署出来的 Worker 地址一致。不知道 Worker 地址就先随便填，部署完再回来改。

点 **Register application** → 复制 **Client ID** → 点 **Generate a new client secret** → 复制 **Client Secret**（只显示一次，先存好）。

### 2. 部署登录中转 Worker（Cloudflare，免费）

1. 打开 https://dash.cloudflare.com/ → 左侧 **Workers & Pages** → **Create** → **Workers** → 名字填 `wusitech-cms-auth` → **Deploy**
2. 进入这个 Worker → **Edit code** → 把仓库里 [`tools/cms-oauth-worker/worker.js`](../tools/cms-oauth-worker/worker.js) 的内容**全部**粘贴进去 → **Deploy**
3. 同一个 Worker 页面 → **Settings** → **Variables and secrets**，逐个添加：

   | 名称 | 类型 | 值 |
   | --- | --- | --- |
   | `GITHUB_CLIENT_ID` | Text | 第 1 步的 Client ID |
   | `GITHUB_CLIENT_SECRET` | **Secret** | 第 1 步的 Client Secret |
   | `ALLOWED_GITHUB_USERS` | Text | 你**登录 GitHub 的用户名**。本仓库提交记录里的作者名是 `Yon_WuSi`，按这个填（不确定就**留空**：留空则不校验用户名，此时只有该仓库的 collaborator 能进后台，Sveltia 自己也会校验仓库写权限）|
   | `ALLOWED_ORIGINS` | Text | `https://wusitech.github.io,https://wstk.pages.dev,http://localhost:1313` |

4. 浏览器打开 `https://<你的Worker地址>/` → 显示 `sveltia-cms-auth: ok` 就说明 Worker 正常

### 3. 把地址回填到仓库

编辑 [`static/admin/config.yml`](../static/admin/config.yml)，把

```yaml
base_url: https://REPLACE-ME.workers.dev
```

改成你的 Worker 地址（形如 `https://wusitech-cms-auth.你的子域.workers.dev`），提交。

### 4. 使用

> **登录失败时怎么查**（Worker 的报错页面会直接写出原因）：
> - **点按钮没反应**：浏览器拦了弹窗，允许本站弹窗后重试
> - **`origin not allowed`**：把访问后台的域名加进 `ALLOWED_ORIGINS`（`https://` 开头，逗号分隔）
> - **「这个 GitHub 账号（xxx）没有后台权限」**：把括号里那个**登录名**填进 `ALLOWED_GITHUB_USERS`，或清空该变量
> - **GitHub 报 `redirect_uri_mismatch`**：OAuth App 里的 callback 与 Worker 实际地址不一致，按实际地址改
> - **后台一直转圈**：浏览器打开 `<Worker地址>/`，应显示 `sveltia-cms-auth: ok`；不显示就是 Worker 没部署成功

- 打开 https://wusitech.github.io/admin/ → **Continue with GitHub** → 授权
- 左侧只有两块：**文章**、**页面**（关于 / 友情链接）
- **保存 = 直接提交到 `main`**，GitHub Actions 约 1 分钟后自动构建部署，跟手动改文件完全等价
- **手机上也能用**：同一个网址，浏览器登录一次即可
- 选图：媒体库指向 `static/images/`，**「全局资源」里能看到站点现有的全部图片和子目录**
  （`banner.webp`、`stm32/…` 等），可以直接挑一张当封面或正文插图
  - 新上传的图片会自动转成 **WebP**（质量 80）再落盘，所以文件管理里存的就是 `.webp`，
    插入的路径也是 `/images/xxx.webp`：
    - 开关在 `static/admin/config.yml` 的 `media_libraries.default.config.transformations`
      （字段定义来自本仓库自带的 `static/admin/sveltia-cms.js` 里的配置 schema；
      `webp: false` 表示「已经是 webp 的图不再转一遍」）
    - 已经是 webp 的、以及**动图 gif / 动图 webp** 会原样保留（转码会毁掉动画）
    - 新上传的图落在 `static/images/` 根目录，可以自己在后台新建子目录归档
  - 站点其它目录的图片（例如 `static/avatar/avatar.webp`）不在媒体库里显示
  - 后台媒体对话框里的**外链图库（Pexels / Pixabay / Unsplash / Lorem Picsum）已在 `static/admin/config.yml` 里关闭**
    （`media_libraries.stock_assets: false`）——本站不依赖外部资源；「输入 URL」仍保留，偶尔贴外链时可用
  - **绕过后台**（直接在 GitHub 网页上传、或用别的工具提交）塞进 `static/images/` 的
    jpg/png/heic 由 [`.github/workflows/webp.yml`](../.github/workflows/webp.yml) +
    [`tools/auto_webp.py`](../tools/auto_webp.py) 在 push 后自动转码、改写引用、删掉原图；
    手工批量处理用 `python tools/auto_webp.py --apply --range origin/main..HEAD`（不加 `--apply` 是预演）
  - 想手工调质量/尺寸：用仓库里的 [`tools/img2webp.py`](../tools/img2webp.py)
- **站点配置（菜单、首页分类、主题参数）没有放进后台**：CMS 保存时会按表单字段重写整个文件，会把没声明的配置项丢掉。要改这些请直接编辑
  https://github.com/WuSiTech/WuSiTech.github.io/edit/main/config/_default/params.yml

## 二、评论系统（Twikoo + Netlify + MongoDB Atlas，全程免费）

为什么是这套：Twikoo 官方对免费部署方案的国内速度评级里，**Netlify 是 ★★★★☆ 且明确写"有充足的免费额度，中国大陆访问速度不错"**；Vercel 国内常打不开；Cloudflare 的 `*.workers.dev` 官方确认在国内有 DNS 污染；腾讯云 CloudBase 免费版**无法配置跨域白名单**，Twikoo 官方要求付费个人版（¥19.9/月）。
评论者只需填昵称（邮箱/网址选填），输 QQ 号会自动补全 QQ 昵称和头像 —— 不要求任何 GitHub 账号。

### 1. MongoDB Atlas（免费 512MB 数据库）

1. https://www.mongodb.com/cloud/atlas/register 注册
2. 建一个免费 **M0** 集群，Region 建议选**新加坡**或**香港**（离大陆近）
3. **Database Access** → Add New Database User → 设用户名密码（记下来）
4. **Network Access** → Add IP Address → **Allow Access from Anywhere**（`0.0.0.0/0`）
5. **Clusters** → Connect → Drivers → 复制连接串，形如
   `mongodb+srv://用户:密码@xxx.mongodb.net/?retryWrites=true&w=majority`

### 2. Netlify 部署 Twikoo 云函数

1. Fork https://github.com/twikoojs/twikoo-netlify 到你自己的账号
2. https://app.netlify.com → **Add new site** → **Import an existing project** → GitHub → 选刚 fork 的仓库
3. 添加环境变量 `MONGODB_URI` = 上一步的连接串 → **Deploy**
4. 部署完成后打开 `https://<你的站点>.netlify.app/.netlify/functions/twikoo`
   看到 **「Twikoo 云函数运行正常」** 就成功了（这个完整地址就是 `envId`）

### 3. 先自检，再回填 envId

```bash
python tools/check_twikoo.py https://xxx.netlify.app/.netlify/functions/twikoo
```

它会检查 4 件事：地址可访问且确实是 Twikoo 服务、云函数版本、**CORS 跨域头**、匿名读接口。
其中 CORS 是最隐蔽的坑 —— 后端没配对时页面上只显示「加载失败」，看不出原因；脚本会直接告诉你
`Access-Control-Allow-Origin` 有没有允许你的博客域名。**四项全通过再往下填**。

然后编辑 [`config/_default/params.yml`](../config/_default/params.yml) 的 twikoo 段：

```yaml
twikoo:
  enable: true
  envId: https://xxx.netlify.app/.netlify/functions/twikoo
  region: # Netlify 部署留空
```

提交后文章页就会出现评论区（`enable: true` 而 `envId` 为空时不会渲染，所以现在线上没有任何变化）。

### 4. 管理评论与反垃圾

- 打开任意文章页 → 评论区右下角的**管理**入口 → 首次进入设置管理员密码
- 管理面板里可以：审核 / 隐藏 / 删除评论、开启**人工审核**、配置垃圾评论关键词、查看访客 IP 属地
- 单篇文章关闭评论：在该文章 front matter 里加 `comments = false`

### 前端已自托管（不请求任何第三方 CDN）

- 评论 JS：`static/resources/twikoo@2.0.15/dist/twikoo.min.js`（`twikoo.min.js` 不含腾讯云 SDK，体积更小，适合 Netlify）
- 由 [`data/vendor.yml`](../data/vendor.yml) 里的 `local|twikoo@2.0.15/dist/twikoo.min.js` 指向，最终地址是 `/resources/twikoo@2.0.15/dist/twikoo.min.js`
- 简体中文是 twikoo 内置默认语言，不需要语言分片文件
- ⚠️ `data/vendor.yml` 是从主题复制过来的**完整副本**（Hugo 对 data 文件是整文件覆盖，不是深度合并）。升级主题后，建议重新复制主题那份、再把 twikoo 这行改成 `local|` 的新版本
- 升级 Twikoo 前端：把新版本下载到 `static/resources/twikoo@<新版本>/dist/`，再改 `data/vendor.yml` 那一行

```bash
curl -L -o static/resources/twikoo@2.0.15/dist/twikoo.min.js \
  https://registry.npmmirror.com/twikoo/2.0.15/files/dist/twikoo.min.js
```

### 常见故障

- **评论整片加载失败，后端返回 `code=1000` + `querySrv ... mongodb.net`**：
  MongoDB Atlas 的免费 M0 集群被**暂停**（长期不活动会暂停），去 Atlas 的
  **Database → Clusters** 看能否 Resume；恢复后博客这边不用改任何配置。
  （Twikoo 官方的 Netlify 演示后端现在就是这个状态，实测报
  `querySrv ENOTFOUND _mongodb._tcp.cluster0.tn2aka2.mongodb.net`。）
- **后端本身正常、页面却提示加载失败**：九成是 CORS，跑
  `python tools/check_twikoo.py <envId>` 看第 3 项。

### 免费额度够用吗

Netlify Functions：**12.5 万请求/月 + 100 小时/月**；MongoDB Atlas M0：**512MB 存储**。个人博客远远用不完。
