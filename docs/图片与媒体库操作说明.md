# 图片与媒体库操作说明

回答三个实际问题：**怎么删照片、怎么"移动"照片、怎么把图片变成 WebP**。

关于写作后台（Sveltia CMS 0.241.0，仓库自带的 `static/admin/sveltia-cms.js`）的行为，
本文所有结论都来自那份 bundle 的**实际代码**，会标「代码证据」；没有在代码里找到确证的
地方会明确写「我的推测」。界面文案按**英文界面**给出（bundle 里只内置了英文词条，
其它语言是运行时从 CDN 拉的，所以浏览器语言不同可能显示中文）。

---

## 一、怎么删除照片

### 1. 删除入口在哪

**入口不在「选择图片」弹窗里，在左侧导航的资产库页面里。**（代码证据）

| 位置 | 怎么进 | 能干什么 |
| --- | --- | --- |
| **资产库页面** `/assets` | 左侧导航栏那个**照片图标**那一项（英文 `Assets`；快捷键 `Alt+2`）| 批量选择、下载、复制 URL、**删除**、重命名、替换、新建文件夹、上传 |
| **单张图片详情页** `/assets/images/xxx.jpg` | 在资产库页面选中一张图 → 工具条上的 `Preview`（或点卡片上的预览） | 看尺寸/提交信息、改文件名、**删除**这张 |
| 文章编辑器里图片字段的 `Select` 按钮 | 字段上点 `Select` / `Browse` | **只能挑图**（弹窗标题 `Select Image`，确认按钮 `Insert`），**没有任何删除入口** |

**代码证据**：删除按钮组件 `m5` 在整份 bundle 里只被实例化 4 次 —— `r$e`（外部图库的详情面板）、
`r1e`（外部图库的工具条）、`E0e`（本地图库的单图详情页）、`V0e`（本地图库的资产页工具条）。
按钮本身是：

```js
// V0e（本地仓库资产页工具条）：
m5(c, { assets: R(s),
        disabled: R(e),                       // e = MP.current || NP(assets)
        deleteAssets: async e => { await U0(e) },   // U0 = 真正落盘删除
        planDeletion: D0,                     // 删前先算「计划」并检查引用
        buttonDescription: J(`delete_selected_assets`, {values:{count:R(s).length}}) })
// m5 内部：按钮 label = J(`delete`)（"Delete"），点开确认框，标题 = J(`delete_assets`)
```

- **一次删多张**：卡片左上角的复选框勾多张（或 `Select All`），工具条上的 `Delete` 会显示数量；
  全选时确认框正文变成 `Are you sure you want to delete all the assets?`。
- **没有右键菜单、没有长按菜单、没有 Delete 键快捷键**（代码证据：全 bundle 里 `oncontextmenu`
  只出现在 app-shell 上用来 `preventDefault`；`keyShortcuts` 只有 `Accel+F` 搜索、`Accel+S` 保存、
  `Accel+E` 新建、`Alt+1..9` 导航）。
- **删除 = 一次 GitHub 提交**。确认后会产生 `Delete "图片路径"` 的提交（`commitType: "deleteMedia"`），
  所以删掉之后想找回，可以在 GitHub 的历史里找到那个提交并还原。

### 2. 为什么「选择图片」弹窗里看不到删除

**因为弹窗里根本没有删除功能，不是被某个开关藏起来的。**（代码证据 + 我的推断）

- 代码证据：删按钮 `m5` 只在那 4 个地方出现，**没有一个在选择弹窗的组件链里**；重命名菜单
  `kQe` 只在 3 个地方出现，同样都不在弹窗里。
- 代码证据：bundle 里搜 `selectionMode` **0 命中**（`picker` 的命中全是 `showDirectoryPicker`、
  `file-picker` CSS 类、日期字段的 `picker_utc` 等无关项）。所以不存在"选择模式把删除隐藏了"这种逻辑。
- 我的推断：这是产品设计取舍 —— 弹窗的职责就是"挑一张图"，删除这种破坏性操作被刻意留在了资产管理页。

**结论：要删图，先关掉/离开选择弹窗，去左侧导航的 `Assets` 页面删。**

**按钮是灰的怎么办？**（代码证据）删除按钮的 `disabled` 条件是
`MP.current || NP(assets)`：
- `MP` = 演示模式（demo mode）**或** 当前登录令牌对该仓库没有 push 权限（`canPush === false`）；
- `NP(assets)` = 图片位于只读目录（`folder.readonly`）。

所以「按钮灰着点不动」通常是**令牌权限不够**：换一个有该仓库 `Contents: Read and write` 权限的
令牌登录（`Assets` 页面顶部也可以看当前登录的账号）。注意给评论系统用的那个细粒度令牌是**只读**的，
不要拿它登后台。

### 3. 「被文章引用就删不掉」到底怎么判定

**判定范围：只扫后台管理的文章（entry）的字段值。**（代码证据）

删除前会先算一份"计划"：`D0(assets)` → `RBe(assets)`，四步：

1. `PBe` —— 把每张图换算成公开 URL（`aY(asset, {allowSpecial:true, pathOnly:true})`，例如 `/images/a.jpg`）；
2. `UFe(refs, {entries: kj.current})` —— 在**后台当前加载的全部 entry** 里，找出引用了这个 URL 的那些。
   `kj.current` 就是 `content/**` 里被 `config.yml` 的 collections 覆盖到的文章/文件；
3. `LBe` / `IBe` —— 在字段值里用 markdown 图片/链接正则
   `NY = /!\[(?:[^\]\n!]|!(?!\[)|\](?!\())*\]\(((?:[^\n!)]|!(?!\[))+?)(?:(?<!\s)\s+"(?:[^"\\\n]|\\.)*")?\)/g`
   匹配引用，并把匹配到的引用**摘掉**（图片字段清空、列表项删除）；
4. `C0` —— 把摘掉之后的 entry 重新跑一遍字段校验，**只有校验不过的**才算"拦路虎"：

```js
C0 = ({draft, entry, collection, collectionFile, locale, content, fields}) => {
  let s = MQ({collection, collectionFile}) || y0(entry);   // 该集合/文件是不是 readonly
  return [...fields].flatMap(([keyPath, fieldConfig]) => {
    let c;
    if (s) c = [J(`readonly_reference`)];                   // 只读集合 → 拦
    else {
      let t = _1({draft, locale, keyPath, value: content[keyPath], valueMap: content, ...});
      if (!t || t.valid) return [];                         // 摘掉之后仍然合法 → 不拦
      c = b$({validity: t, fieldConfig});
    }
    return [{collectionLabel, fieldLabel, entry, summary, keyPath, messages: c}];
  });
};
```

**所以有两种结果，看确认框里写了什么就知道：**

| 确认框里的提示 | 含义 | 怎么办 |
| --- | --- | --- |
| `The reference to it in an entry will be removed as well.`<br>（`deleting_referenced_assets_note`） | 引用它的字段**不是必填**，Sveltia 会**顺手把文章里的引用也删掉**，然后删图 | 直接确认即可；但**建议先自己把引用去掉再删**，免得文章被静默改动 |
| 列出「集合 › 文章 + 字段名」，标题是 `This asset can't be deleted, because the following fields in the entries using it would no longer be valid without it. Update those entries first.`<br>（`cannot_delete_referenced_assets`） | 摘掉引用后字段**校验不过**（例如 `required: true` 的图片字段），**确定按钮是灰的** | 先改文章（见下） |

真去删还会抛一句英文硬编码错误（没走 i18n，所以界面上会显示成删除失败）：
`Cannot delete assets that entries require`（代码证据：`U0` 里
`if (i.length) throw Error('Cannot delete assets that entries require', {cause:i})`）。

**我们站的实际配置**（代码证据，`static/admin/config.yml`）：`cover` 和 `banner` 都是
`required: false`，`description` / `categories` / `tags` 也是 `required: false`，只有 `title`、
`date`、`draft`、`body` 是必填 —— **图片字段没有一个必填**。所以在**当前配置**下，
图片被文章引用时应该走上面第一行（顺手清引用），不会出现"删不掉"。如果你真的看到
"can't be deleted" 那种列表，检查是不是把某个图片字段改成了 `required: true`。

**⚠️ 一个必须知道的盲区**（代码证据）：扫描只看后台管理的 entry，**不扫** `config/`、`data/`、
`layouts/`、`themes/`。也就是说：

- 图片只被 `config/_default/params.yml`（站点 logo / 头像 / 太极图标）、`data/covers.yml`、
  `data/friends.yml`、主题模板引用时，后台会**痛快地删掉**，站点随后断图（Hugo 构建不会报错！）。
- **封面池的 374 张原图不在媒体库里**：它们在 `media` 分支，后台只从下拉框按站内路径选，
  所以「全局资源」里看不到它们、也不会被后台误删。加图请提交到 media 分支，
  见 [图片池（media 分支）.md](图片池（media%20分支）.md)。
- 删之前先自己查一遍（themes 是 git 子模块，要单独搜）：

```bash
git grep -n '你要删的文件名'                 # 查 content / config / data / layouts 等
git grep -n --recurse-submodules '文件名'    # 连 themes/ 子模块一起查
```

### 4. 站长该怎么做（删图步骤）

1. **先查引用**：`git grep -n '<文件名>'`（+ 带 `--recurse-submodules`）。命中 `themes/` 的话，
   **不要删**（那是主题素材）。
2. **把文章里的引用去掉**：打开相关文章 → 清空 `首页缩略图(cover)` / `文章页顶部大图(banner)`
   字段，或把正文里的 `![](...)` 删掉 → 保存。等它提交完（或至少保存完）。
3. **回到左侧导航的 `Assets` 页面**，找到那张图（可以按名字搜索），勾选它 → 工具条 `Delete` →
   确认框里确认。
4. **删完看一眼**：`git log --oneline -3` 里应该有 `Delete "static/images/xxx.jpg"` 这样的提交；
   过一两分钟看 Actions 里 `Build and deploy` 有没有跑（有的话站点就更新了）。
5. 如果那个字段是必填的（现在不是），还得先把图换成别的，或者把字段的 `required` 改回 `false`。

## 二、怎么"移动"照片

### 1. 后台里没有"移动"这个功能（代码证据）

- **没有任何移动 UI**：整份 bundle 里 `Move asset` / `moveAsset` **0 命中**；`move` 相关的界面文案
  只有一句成功提示 `assets_moved`（"Asset moved."）。唯一的移动代码是
  `G0(action:'move', …)`，它只被两处调用：
  - `U0e`（单图重命名对话框）：新路径 = `` `${dirname(原路径)}/${新名字}` `` —— **目录取的是原目录**；
  - `sVe`（文件夹重命名）：`sVe({dirPath, newDirPath: KF([qF(t), e])})` —— 同样是
    `dirname(文件夹) + 新名字`。
    两条路都只换名字、**不换目录**。
- **重命名不接受带斜杠的路径**（所以 `a.jpg` → `sub/a.jpg` 这条"曲线移动"也走不通）：

```js
// 文件名校验（重命名对话框用）
jFe = ({name:e, fileName:t, otherNames:n, folderNames:r=[]}) => {
  if (!e) return `empty`;
  if (e.includes(`/`) || !t) return `character`;   // ← 带 / 直接判为非法字符
  if (e.startsWith(`.`)) return `leading_dot`;
  ...
};
// 对应提示：enter_new_name_for_asset_error.character
//          = "File name cannot contain special characters."
```

  另外名字会先过一遍 `WF()`（`sanitize-filename`）把路径分隔符等非法字符洗掉，`bY()` 再去掉开头的点。

- 你看到的 `Rename`（bundle 里 24 行命中）就是这套：`rename` / `rename_asset` / `rename_x` /
  `enter_new_name_for_asset` + 上面那个校验。

**结论：后台能做的只有「同目录改名」和「整个文件夹改名（里面的图跟着一起动）」，
不能把图片（或文件夹）挪到另一个文件夹里去。**

### 2. 后台内最接近的做法

| 想做的事 | 后台里怎么做 |
| --- | --- |
| 改个文件名（还在 `static/images/` 根下） | `Assets` → 点一下那张图选中它 → 工具条**最右边那个"资产信息"按钮** → 在弹出的面板里点 `…`（`Show Edit Options`）→ `Rename`；或进单图详情页，右侧 `…` → `Rename`。改名对话框会显示引用它的文章数，并提示引用会一起被更新 |
| 把一个文件夹改名（文件夹里所有图一起动，引用也会一起改） | `Assets` → 鼠标移到文件夹那一行 → 行内菜单 → `Rename Folder`（会问你是否连带改引用） |
| **把图挪进另一个文件夹** | **后台做不到。** 两条替代路：<br>① 先 `Download` 下载 → 进目标文件夹 `Upload` 上传 → 回原位置 `Delete`（注意：上传到 `static/images/` 会走后台的 WebP 转码，落盘的名字/格式可能变）<br>② 用下面这个脚本一步做完「移动 + 改引用」 |

**代码证据**：本地图库资产页工具条（`V0e`）依次是 `Preview`（`X$e`）、资产信息面板（`h0e`→`DQe` 的
`Show Edit Options` 里有 `Edit` / `Rename` / `Replace`）、`Download`（`g5`）、`Delete`（`m5`）、上传 FAB。
单图重命名对话框是 `U0e`，提交时走
`G0('rename', [{asset, path: `${dirname(原路径)}/${新名字}`}])` —— 目录部分取的是**原目录**。
如果引用这张图的文章所在的集合是**只读**的，重命名会被拦下来，提示 `cannot_move_referenced_asset`
（"This asset can't be moved or renamed, because the following read-only entries use it"）。

### 3. 改名/移动一定会断引用 —— 必须同步改

改完名字（或挪了位置）之后，**所有写死旧文件名的地方都会指向一个不存在的文件**。
本仓库现在真正用到图片引用的地方（`git grep` 实测）：

| 位置 | 实际写法示例 |
| --- | --- |
| 文章 front matter | `content/posts/stm32f4-interrupt.md`：`cover = "images/stm32/interrupt-path.webp"`、`banner = "images/banner.webp"`（**注意没有前导斜杠**） |
| 正文 markdown | `![](/images/stm32/interrupt-path.webp)` |
| `config/_default/params.yml` | `url: "../images/taichi.png"`、`avatar:`、`logo:` 等（相对 `css/` 的路径） |
| `data/covers.yml`、`data/friends.yml` | `/images/stm32/interrupt-path.webp` |
| `themes/reimu/**`（**git 子模块**） | `{{ "images/reimu.png" \| relURL }}`、`../images/taichi.png`、`../images/cursor/*.png` |

**`static/images/reimu.png`、`static/images/taichi*.png`、`static/images/cursor/*.png`
是主题写死引用的，绝对不要改名/删除/转格式。**

### 4. 用 `tools/rename_image.py` 一步到位

这个脚本就是为"移动照片 + 同步改引用"写的（因为后台做不到）。

```bash
# ① 先预演（默认就是 dry-run，不会动任何文件）
python tools/rename_image.py static/images/photo.jpg static/images/posts/photo.jpg

# ② 看着没问题再落盘：移动文件 + 改 content/、config/、data/、static/ 里的引用
python tools/rename_image.py static/images/photo.jpg static/images/posts/photo.jpg --apply

# ③ 看一眼改动，自己提交（脚本绝不做 commit / push）
git status --short
git add -A && git commit -m "图片移到 posts/：photo.jpg" && git push
```

它做的事：

- 移动（`shutil.move`，目标目录自动创建；改完 git 会识别成 rename）；
- 改引用：`content/**`、`config/**`、`data/**`、`static/**` 里 **带路径** 的引用（
  `/images/a.jpg`、`images/a.jpg`、`../images/a.jpg`、`static/images/a.jpg`、
  `https://站点/images/a.jpg` 都认），把路径尾部的相对路径整段换掉，
  例如 `../images/a.jpg` → `../images/posts/a.jpg`（前缀原样保留）；
- 只报告不改：`layouts/**`、`i18n/**`、`functions/**`、`archetypes/**`、`themes/**`
  里如果还有旧引用，会列出来让你自己处理（`--strict` 时会以退出码 1 结束）。

安全校验（任何一条不过就**什么都不改**、退出码 2）：

| 检查 | 说明 |
| --- | --- |
| 原图必须存在、必须是图片、不能是空文件 | |
| 目标不能已存在 | 拒绝覆盖 |
| 扩展名必须一致 | 防止"改了名但没转格式"；确实要改加 `--allow-ext-change` |
| 路径不能是绝对路径、不能含 `..`、不能出仓库 | |
| 必须在同一个媒体库里 | 默认 `static/images`；别的目录用 `--media-root` 指定 |
| 图片被 `themes/` 引用 | **默认拒绝**（子模块里的引用脚本不改）；确实要动加 `--force` |
| 有**裸文件名**引用（只写 `a.jpg`，没有路径） | 同目录改名会安全地改成新名字；**换目录时默认拒绝**，因为无法判断它相对谁。确认过就加 `--rewrite-bare` |

> 为什么裸引用要拦：`a.jpg` 到底相对谁？页面 URL 还是 `images/`？换目录后改成
> `sub/a.jpg` 可能对、也可能错。宁可不猜。

自测：`python tools/test_rename_image.py` → `RESULT: ALL PASS (71/71 项)`。

### 5. 改完记得重新部署

引用改了必须等 Hugo 重新构建才生效：push 到 `main` 会自动触发 `Build and deploy`；
也可以去 Actions → `Build and deploy` → `Run workflow` 手动跑一次。

## 三、怎么把图片变成 WebP

三条路，按省事程度排：

### 1. 上传前先在本地转（最省事，不依赖任何 CI）

```bash
python tools/img2webp.py 目录 -r -q 78 --max-dim 1600
```

- `-r` 递归子目录；`-q 78` 有损质量；`--max-dim 1600` 限制最长边（只缩不放）；
- 加 `--target-kb 300` 可以按体积上限压；`--dry-run` 只报告；`-o out/` 输出到别处；
- HEIC / AVIF（iPhone 照片）需要额外装插件：`pip install pillow-heif`（本机已装 Pillow 时才有用）。

### 2. 后在台上传时自动转（本站主路径，已经配好）

`static/admin/config.yml` 的 `media_libraries.default.config.transformations` 已经把
`jpeg / png / heic / avif / gif → webp`（quality 80），`webp: false`（已经是 webp 的不再转）。
**在 `/admin/` 里上传 jpg，落盘就是同名 `.webp`**，不需要你做任何事。

（这段配置的依据写在 `config.yml` 的注释里，全部来自 bundle 里的 schema
`RasterImageTransformationOptions` 和运行时函数 `RSe()/DF()/dF()/dSe()`：
只缩不放、跳过动图 gif / 动图 webp / 交错 png、quality 必须是 0-100 整数。）

### 3. push 之后由 Action 兜底转（绕过后台的图片）

`.github/workflows/webp.yml` + `tools/auto_webp.py`：把**本次推送**里新增/修改的
`static/images/**` 位图转成同名 `.webp`、把 `content/**`、`config/**`、`data/**`、`static/**`
里对旧文件名的引用改成 `.webp`、删掉原图，然后自己提交（提交信息带 `[skip ci]`）。

- **触发条件**：`push` 到 `main`，且改动命中 `static/images/**`。
- **不会重复触发自己**：机器人提交信息带 `[skip ci]`，GitHub 会跳过这次 push 触发的**所有**
  workflow（包括它自己）。代价见下面「已知限制」。
- **手动触发**：Actions → `Auto WebP` → `Run workflow`，`range` 参数：
  - 填 **`all`**（默认）= 扫 `static/images/**` 下**所有**还不是 webp 的位图 → **一次性转存量图片**；
  - 或填任意 git 范围，如 `HEAD^..HEAD`、`origin/main..HEAD`、`<sha>..<sha>`。

### 4. 手动一次性转换存量图片（照这个做）

1. 打开 <https://github.com/WuSiTech/WuSiTech.github.io/actions/workflows/webp.yml>
2. 右上角 **`Run workflow`** → 分支选 `main` → `range` 保持 **`all`** → 点绿色按钮。
3. 等 1~3 分钟。日志里会看到：

   ```
   存量模式（--all）：不比对 git diff，扫描下列目录下所有还不是 webp 的位图：
     · static/images/**
   显式排除（主题素材，一律不动）：
     · static/images/cursor/*.png
     · static/images/reimu.png
     · static/images/taichi*.png
   外加守卫：任何被 themes/ 内文本引用到的图片都会跳过（…）
   ```

4. 如果真有东西要转，会多出一个提交：`chore(images): 自动转 WebP 并改写引用 [skip ci]`。
5. 因为 `[skip ci]` 会把 `Build and deploy` 一起跳过，工作流最后会**自动补一次部署**
   （`gh workflow run hugo.yaml`）。这一步失败时它会打一条 warning，你就到
   Actions → `Build and deploy` → `Run workflow` 手动跑一次。

本地想先看一遍（推荐，安全）：

```bash
python tools/auto_webp.py --all              # 预演：只报告，不改任何文件
python tools/auto_webp.py --all --apply      # 确认之后再落盘
```

**主题素材保护（两道）**：
1. 显式排除清单 `ALL_MODE_EXCLUDE`（在 `tools/auto_webp.py` 里，带注释）：
   `static/images/cursor/*.png`、`static/images/reimu.png`、`static/images/taichi*.png`；
2. 引用守卫 `THEME_REF_GUARD`：**任何被 `themes/**` 里文本引用到的图片一律跳过**。
   因为 `themes/` 是 git 子模块、脚本不（也不该）改写它的引用，转了 + 删原图就一定会让主题断图。
   就算清单漏了一项，这道守卫也能兜住。

### 5. 为什么你那次上传的 jpg 没变成 WebP

**事实（git 证据）**：

```
$ git log --all --oneline --name-status --diff-filter=AMD -- 'static/images/**'
c97d009 Revert "test: e2e 临时提交（待还原）"
D       static/images/e2e-auto-webp-test.jpg
0e73b72 test: e2e 临时提交（待还原）
A       static/images/e2e-auto-webp-test.jpg
5916ce3 更新博客
A       static/images/algolia_logo.svg
A       static/images/banner*.webp … （主题自带素材）
```

- 仓库历史上**从来没有站长上传的图片提交**，唯一一次图片 push 是那次 e2e 测试：
  `0e73b72`（2026-10-16 13:10:26，加了 `static/images/e2e-auto-webp-test.jpg` + 一篇引用它的
  `content/posts/zz-e2e-auto-webp.md`），**39 秒后**就被 `c97d009`（13:11:05）整条 revert 掉了。
- **没有任何机器人提交**：历史里不存在 `e2e-auto-webp-test.webp`，也没有任何带
  `chore(images)` 的提交。
- 那次 e2e 用的测试图，和 `static/images/reimu.png` 是**同一份字节**
  （blob 都是 `df39735862a36ecf57500336bf19ecb6186ee70c`，12394 字节）。

**结论**：
1. **你的图片根本没有进仓库**，所以没有任何东西可以触发转换 —— 这是最主要的原因。
   webp.yml 只监听 `push` 到 `main` 且改动 `static/images/**`；后台上传走的是 CMS 自己的
   提交，如果那次上传/保存没成功（或图片只存在你本机），GitHub 上什么都不会发生。
   **先确认图片真的在仓库里**：GitHub 仓库页面进 `static/images/` 看有没有那个文件。
2. 那次 e2e 测试即便跑到了转换，也会**因为推送被拒而失败**：测试提交 39 秒后就被 revert，
   runner 光装依赖就不止这个时间；等机器人算完、准备 `git push` 时，`main` 已经走到了 revert
   那个提交，push 是 non-fast-forward，**直接失败，什么都不留下**。（这一条是**我的推断**：
   仓库里没有 Actions 日志，我无法直接看那次 run 的结论；但"没有任何机器人提交"和
   "39 秒后被 revert"是确凿的。）
   我已经在 workflow 里加了 **rebase 重试（最多 3 次）**，并且失败时会 `::error::`
   明确报错，不会再静默失败。
3. 顺手排除了一个假说：那张测试图（12 KB 的 PNG 改名成 .jpg）**并不会**因为"转出来更大"
   而被放弃 —— 我在本地按 CI 的方式跑过，12.1 KB → 9.8 KB（-19%），是真会转的。

**现在怎么补救**：如果那张 jpg 确实在仓库里（或你重新上传一次），走上面第 4 步手动
`Run workflow` 填 `all`，或者等下一次 push 自动触发。

### 6. 这条 workflow 会不会和站点构建打架（审计结果）

| 检查项 | 结论 |
| --- | --- |
| `paths` 与 `paths-ignore` 同时写在 `on.push` 下 | **已修**。GitHub 规定同一个事件不能同时用这两个过滤器（要同时包含/排除只能在 `paths` 里用 `!`）。原来两个都写属于依赖实现细节；现在只留 `paths: ['static/images/**']`，防自触发改由 `[skip ci]` 保证 |
| `[skip ci]` 真的生效吗 | **生效，而且范围比想象的大**：它跳过这次 push 触发的**所有** workflow，包括 `hugo.yaml`（Build and deploy）。所以机器人提交之后站点**不会自动重新部署** → 我在 workflow 末尾加了 `gh workflow run hugo.yaml` 补一次（`continue-on-error: true`，失败只打 warning，并提示手动跑） |
| 会不会死循环（转码 → 提交 → 再转码） | 不会。`[skip ci]` 是硬保证；另外脚本本身也幂等（webp 已存在就跳过、`.webp`/`.svg`/`.gif` 都跳过） |
| `permissions: contents: write` 够不够 | 够 push。另外为了 `gh workflow run` 补部署，加了 `actions: write`。前提是 `main` 分支保护规则允许 `github-actions[bot]` 直接推送（如果开了 "Require pull request"，push 会失败并报错，需要把 Actions 加进 bypass 列表） |
| 并发推送 | `concurrency: {group: auto-webp, cancel-in-progress: false}` 已经串行化本工作流；和"站长正在后台保存"这种并发抢推送的情况，现在有 rebase 重试 3 次 |
| `paths-ignore` 会不会漏掉它自己改写的 `content/**` | 已经不存在 `paths-ignore` 了。反之要留意：机器人提交里如果**只**改了 `content/**`（理论上不会，它总是先动图片），不会触发本工作流 |
| 首次提交没有父提交（`HEAD^` 不存在）会不会炸 | 不会。`resolve_range()` 会依次尝试 `GITHUB_EVENT_BEFORE..GITHUB_SHA`（新建分支时 before 是全 0，会跳过）→ `HEAD^..HEAD` → `HEAD`，全都有 try/except 兜底。这条有单测覆盖 |
| `workflow_dispatch` 能不能指定范围 | 能。`range` 输入支持任意 git 范围，也能填 `all` 做存量转换（默认就是 `all`） |

## 四、已知限制

1. **后台不能移动图片**，只能同目录改名 / 改文件夹名（见第二节）。要移动请用
   `tools/rename_image.py`。
2. **改名/移动会断引用**。必须同步改文章 front matter（`cover`/`banner`）、正文 markdown、
   `config/`、`data/`；`themes/` 里的引用不能自动改（子模块），所以**主题素材不要动**。
3. **删除引用检查有盲区**：只扫后台管理的文章字段，不扫 `config/`、`data/`、`layouts/`、`themes/`。
   删图前请 `git grep` 一遍。
4. **`Select Image` 弹窗里不能删图**，必须去 `Assets` 页面。
5. **删按钮变灰**一般是令牌没有该仓库的写权限（或图片在只读目录）。
6. **gif 一律跳过**（当动图处理，怕毁动画）；`svg` 跳过（矢量不栅格化）；已经是 webp 的跳过。
7. **转出来比原图大就放弃**（纯色小图很常见），会保留原图并打印原因。这种图留在原格式就行。
8. **HEIC/AVIF 需要插件**：
   - 本地用 `img2webp.py` 转 iPhone 的 HEIC 需要 `pip install pillow-heif`；
   - CI 里（`webp.yml` 的 venv）只装了 `Pillow`，**没有**装 `pillow-heif`，所以
     **push 进来的 .heic 会转换失败**（脚本会记一笔失败、保留原图、不影响其它图，退出码仍是 0）。
     走后台 `/admin/` 上传 HEIC 则由 CMS 在浏览器里转码（`dSe()`/`DF()` 用 canvas），不受这个限制。
     要根治就是给 venv 加上 `pip install pillow-heif`（同时脚本 `img2webp.py` 已经会在导入时
     自动注册它）。
9. **`[skip ci]` 会让站点部署被跳过**：`webp.yml` 现在会补一次 `hugo.yaml`，但如果你手动禁用了
   Actions 写权限 / 分支规则挡住了，就需要自己去 Actions 手动 `Run workflow`。
10. **`--all` 只扫 `static/images/**`**（`DEFAULT_PATTERNS`），`static/avatar/` 之类的目录
    要另外用 `--patterns` 指；并且被主题引用的图会被守卫跳过。
11. **后台界面语言**：bundle 里只内置英文词条，其它语言运行时从 CDN 拉；断网环境会显示英文
    （偶尔会看到 `locale_load_failed` 的提示，不影响使用）。
