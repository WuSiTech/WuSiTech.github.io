> 一份项目记录。主角是一块二十块钱左右的 STC8 单片机做的掌上示波器：
> 把固件从原版移植到 45 MHz 的 56DZ 核心板，并补上了信号源、串口数据流、
> 电脑上位机、双光标测量、开机自检，以及一整套可校准的时基系统。
>
> 仓库：[WuSiTech/mini-dso](https://github.com/WuSiTech/mini-dso)（固件、上位机、README 都在里面）

## 一、缘起：原版、板子和 45 MHz

一切的起点是 CreativeLau 的开源项目 **Mini-DSO v0.3**：STC8 单片机 + 128×64 OLED +
EC11 旋钮，做成一个能塞进口袋的示波器。后来有玩家把它适配到了 **56DZ 版硬件**
（对应 Elektor 的 reverse-engineering 项目），我们拿到的就是这块板子。

原版固件跑的不是 45 MHz，而 56DZ 板载的 STC8A8K64D4 我们习惯让它跑 **45 MHz 内部 IRC**。
主频一改，所有和"时间"有关的东西全部要重算：

- 采样间隔（时基）
- ADC 的时钟分频
- 串口波特率（Timer2）
- 波形发生器与方波的定时器

这一轮改造的成果是：**21 档时基、从 500 ms/div 一直到 80 µs/div**，
每档都用实测值重新标定，而不是照搬原版表格。

## 二、第一场硬仗：时基校准

一开始时基误差高达 ±60%，因为"延时函数"的实际耗时和原版假设完全不一样。
解决思路不是拍脑袋，而是**测**：

1. 让固件从 P1.1 输出一个已知分频的测试方波（`0x15` 命令）
2. 电脑端采集波形、数一个周期占多少个采样点
3. 反推出真实的采样间隔，逐档修正延时表
4. 把 21 档修正值写进 EEPROM

这套流程后来被做成上位机的**「一键校准」**：自动驱动设备输出参考方波、
逐档测量、把校准表回写，全程 1~2 分钟。

- 校准表格式：21 × `uint16`，存 EEPROM（带 magic `'CL'` + 校验和）
- 串口命令：`0x16` 写表 / `0x17` 读表

最终误差：慢档 ≤ ±1%，常用档 ±2% 以内。

## 三、让示波器会说"串口话"

原版只有屏幕，没有电脑端。我们做的第二件事是**给固件加一条完整的串口数据流**，
并配套写了一个 Python 上位机。

**帧格式**：`A5 5A TYPE LENH LENL PAYLOAD SUM`

> 最新进展（固件 v1.7.17）：时基 21 档已逐档实测校准（表格存 EEPROM），右上角频率读数改用实测采样间隔表 DtTbl 计算；
> 方波生成改为 Q8 小数累加器，15 档频率实测误差 ≤5%（42 kHz 档可用）；波形输出的 6 档频率步进也做了逐档标定。
> 所有系数（TK、WS、模型系数）都放在 EEPROM 里，在设备的两个偏移表页即可调整，不再需要重新烧录。

| 类型 | 方向 | 内容 |
|---|---|---|
| `0x01` | 设备→PC | 采样帧：28 B 头 + 100 × `uint16` 原始 ADC |
| `0x02` | 设备→PC | ACK |
| `0x03` | 设备→PC | 参数块（22 B） |
| `0x10/0x11/0x12` | PC→设备 | 下发参数 / 存 EEPROM / 读参数 |
| `0x14` | PC→设备 | 软复位进 ISP（为自动烧录服务） |
| `0x15` | PC→设备 | 输出测试方波 |
| `0x16/0x17` | PC→设备 | 写 / 读时基校准表 |
| `0x19` | 设备→PC | 固件版本 / 参数块长度 / 能力位 |
| `0x1A/0x1B` | 双向 | 读 / 设波形滚动位置 |
| `0x1C` | PC→设备 | 运行 / 暂停 |

采样帧头里塞了：运行标志、时基档、绘图模式、触发方式/沿、VMax/VMin、实测频率、
屏幕电压上下限、ADC 上下限、BGV、分压系数……
这些让上位机可以**精确地把原始 ADC 换算成电压刻度**，而不是自己猜。

上位机本身是 Tkinter 写的（`py/dso_gui.py`）：实时波形、FFT、自动测量
（Vpp/Vmax/Vmin/Vrms/Vavg/频率/周期/占空比/上升时间）、双光标 Δt/ΔV、
CSV/PNG 导出、无硬件时的 `--demo`、协议自检 `--selftest`。

## 四、自动烧录：让固件自己进 ISP

STC8 烧录需要"冷启动"进 ISP bootloader。反复拔插电源太麻烦，于是：
上位机发 `0x14` → 固件回 ACK → 延时约 1 秒 → `IAP_CONTR = 0x60`（软复位进 ISP）
→ `stcgal` 立刻接上烧录。配合 `py/flash.py`，一次点击就能"改代码→烧录"。

> 期间踩过的坑：这块板的 DTR/RTS 并不能复位 MCU，所以必须靠固件自己跳。
> 另外 stcgal 成功时也可能返回非零退出码，脚本里改成解析 `Disconnected!` 来判断。

## 五、功能扩展（从"能看"到"好用"）

### 1. 可调信号源

- **P1.1 方波**：15 档频率（约 1 Hz ~ 42 kHz）+ 占空比 1~99 %
- **P1.0 波形**：PCA 8-bit PWM 输出 正弦 / 三角 / 锯齿，外部 RC 滤波后就是模拟波形

这里有个有意思的细节：最初周期表是"抄"出来的经验值，后来越补越乱。
最后改成**运行期计算**——所有频率都从一个常量 `GEN_TICK_US10`
（1 tick = 12.0 µs，实测值）算出来，同时顺手修掉了一个占空比被 `uint8` 截断的老 bug
（低频时占空比完全不对）。

### 2. 中英双语与中文点阵

设备只有 128×64 点阵屏，没有现成中文字库。我们的做法：

1. 用 Pillow + 宋体渲染 **12×12 像素**汉字
2. 生成 `cnfont.h`（字模 + 字符串索引表）
3. 加一个"按像素精确贴字"的绘制函数

第 3 步是重点：原来的 `OLED_DrawBMP()` 只支持 8 像素对齐的起点，
而行距是 12 像素时汉字会被切边、错位。我们写了一个
`OLED_DrawGlyph12()`，把 12×12 字形按位搬到任意 y（跨 2~3 个页），
并且支持"反色模式"——设置页的白色高亮条就是这样来的。

### 3. 双光标测量（设备端）

在设备上新增一页光标测量：两条竖直光标、可切换 A/B、可左右移动，
底部直接显示 **`dT` / `dV`**。这一页和上位机的光标功能是各自独立的实现，
但读的是同一套采样数据。

### 4. 开机自检 + 启动页

上电先显示 LOGO + `C.L./W.S.&D.S`，底部一行自检结果：
`EEP:OK CAL:OK 1.18V` —— 分别检查 EEPROM 是否有效、校准表是否合法、电池电压是否正常。

### 5. 设备端校准表页面

以前校准只能靠电脑。现在设置里多了「校准表」一页，可以直接在设备上：

- 按住 + 旋转：选择要调的档位（0~20）
- 旋转：微调该档校准值（慢转 ±1，快转 ±8）
- 长按：立刻写 EEPROM 并提示保存成功

## 六、交互重构：从"中断里忙等"到状态机

原版固件的按键处理全在 INT1 中断里：

```c
Delay50ms();                  // 消抖
if (Delay800ms_Long_Press())  // 判断长按
if (Delay300ms_Double_Click())// 判断双击
```

一次按键最多阻塞 **1.15 秒**，期间 72 kHz 的波形输出中断、编码器采样、串口全部停摆。
更糟的是，这套逻辑让按键行为变得不可预测。

我们把它重构成：

- **INT1 只记录"按下时刻"**（外加一个 `ADCInterrupt=1` 打断当前扫描）
- **Timer0 每 1 ms 跑一次 `Key_Tick()`**，负责计时、消抖、判定短按/长按/双击
- **主循环 `Key_Poll()`** 只负责执行排队的动作

改完以后：长按不再打断信号源输出；所有"看起来卡死"的界面里也插入了 `Key_Poll()`，
不会再出现某个页面按键失灵。

顺手修掉一个隐蔽 bug：机械按键按下时触点会在 A/B 线上抖动，
之前每次抖动都被当成"按住旋转"，导致正常的短按被丢弃——于是有了"时好时坏"的手感。
现在只有真正转出一格才算"按住旋转"。

## 七、暂停与滚动：一个被反复推翻的设计

"波形滚动"这个功能我们推翻重做了三次：

1. **原版**：双击切换全局滚动模式，旋转 = 左右滚波形
2. 我们第一版：把双击去掉（和 Run/Stop 冲突），改成设置页里的开关
3. 最终版：**滚动只在暂停时有意义**，所以做成"暂停时多出来的第 6 个选中项"：
   按住旋钮把光标切到左下角那条"触发位置标尺"，标尺整条反色，
   此时旋转就是左右滚动；切到别的项就恢复调参数

配套地：

- 暂停时按一下 = 继续（恢复运行不清屏，先保留旧波形，等新扫描完成再刷新）
- 上位机暂停按钮会**同时暂停单片机**（`0x1C`），并且在波形下方出现一条
  与设备实时同步的滚动条（`0x1A` 读 / `0x1B` 写）

> 这里也踩了个坑：上位机一开始每 250 ms 轮询一次滚动位置，
> 结果**把采样帧挤掉了**——30 ms 以上的时基看起来"画面完全不动"。
> 后来改成只在暂停时轮询，问题消失。

## 八、工程化的坑

### 1. 8051 的 128 字节

功能越加越多，某次编译突然链接失败：

```
?ASlink-Error-Could not get 66 consecutive bytes in internal RAM for area DSEG
```

8051 的直接寻址 RAM 只有 128 B，而我们把它塞满了。
最后发现解法不是"把全局变量搬进 xdata"（试过，没用），
而是给整个工程加 **`--stack-auto`**——让函数局部变量走堆栈而不是固定 overlay 区。
加上之后链接一次通过，还给栈多挤出 80 字节。

### 2. 编译脚本与版本号

原仓库的 Makefile 在 Windows 上跑不起来，我们写了 `build.ps1`：
一条命令编译 `src/*.c` + `user/main.c`、打包库、链接，并输出内存占用。

固件里加了 `FW_VER_MAJOR/MINOR/PATCH` 和 `0x19` 查询命令，
上位机连接时会自动读出来显示在状态栏——排查问题时非常有用
（"你现在跑的到底是哪版固件"）。

### 3. 编码

所有 C 源文件是 **GBK**，中文注释在 UTF-8 编辑器里会乱码；
`cnfont.h` 是生成文件，改字模要改生成脚本，不能手改。这些都写进了 README。

### 4. 看门狗：加了又删

我们试过加软件看门狗（2 秒超时，超时 `IAP_CONTR=0x20` 软复位）。
结果在 500 ms/档时误复位——慢时基跑一轮就要 4.4 秒，
触发等待、长扫描这些状态在软件看来和"卡死"无法区分。
权衡之后**删掉看门狗**，换来的是长时基下不会莫名重启。

## 十、还能做什么

- **双通道**：硬件上 ADC CH1 是现成的，固件目前只用一个通道
- **设备端 FFT**：RAM 和算力都很紧，需要定点 + 抽取
- **真正的硬件看门狗**：需要给所有长等待点（ADC、EEPROM 写、长扫描）都设计喂狗点
- **绝对时间基准**：现在的时基是"自洽"校准的，绝对精度还缺一个外部参考
- **预设保存**：2~3 组常用设置一键切换

## 附：用一块 STM32 蓝色药丸当频率基准，把 21 档时基钉死

示波器校时基最怕"自己测自己"：拿板载信号源自标，误差会互相抵消，看起来校平了，一上外部基准就原形毕露。
我最初就是栽在这上面——自洽校准出来的 21 档，实际误差从 −23% 到 +25%，每档还不一样。

### 为什么用 STM32

手头没有信号发生器、也没有音频线，但有两块 STM32 最小系统板。STM32F103C8T6（蓝色药丸）上有
**8 MHz 石英晶振**，走 HSE→PLL×9 就是 72 MHz，晶振精度典型 ±20~50 ppm。
拿它输出 1 kHz 当基准，基准误差 0.005%——比要修的 20% 误差小四个数量级，完全够用。

### 基准固件（寄存器版，不依赖 HAL）

```c
/* FLASH 等待周期：72 MHz 必须 2WS，缺这一句必跑飞 */
REG32(0x40022000) = 0x12;

/* HSE 8MHz -> PLL x9 = 72MHz，APB1 必须 /2 */
RCC_CFGR = (1<<16) | (7<<18) | (4<<8);

/* TIM2: 72MHz/72 = 1MHz，ARR=999 -> 1 kHz，CCR=500 -> 50% */
TIM2_PSC = 71; TIM2_ARR = 999; TIM2_CCR1 = 500;
```

引脚：**PA0 = TIM2_CH1 复用推挽输出**，接示波器 INPUT 红夹，GND 共地。

### 踩过的坑

- **克隆片**：手上是 HK32F103C8T6，pyocd 会报 `Not a genuine ST Device`，但照样能烧；
  真正坑人的是 `FLASH_ACR` 忘记设 2 等待周期——代码只跑了一半就死，TIM2 寄存器全是复位值
- **APB1 分频**：注释写 /2、代码写成 /1，72 MHz 下 APB1 超频，行为随机
- 烧录：`pyocd flash --target stm32f103c8 --erase chip`，克隆片需要先 `pyocd pack install`

### 校准方法：数"一个周期占多少个采样点"

不依赖设备自己的频率读数（那是待校准对象），而是拿原始采样数据直接数：

1. 基准输出已知频率 f（按档位在 5 Hz / 50 Hz / 500 Hz / 1 kHz / 3 kHz / 10 kHz 之间切换）
2. 抓一帧 220 点原始数据，用迟滞过零点数出"一个周期占 N 个采样点"
3. 真实采样间隔 = (1/f) / N，写进 EEPROM 的 `DtTbl[21]`（uint32，0.01 µs）
4. 设备右上角频率读数改成 `f = 1e8 / (周期点数 × DtTbl[档])`

低频档用 5 Hz、高频档用 10 kHz，保证每个周期都能数到 20~100 个采样点。

### 顺手挖出的三个真 bug

校准时"存了不生效、重启就丢"，一直以为是 EEPROM 空间不够，后来才发现：

- `for (i = 176; i < 260; i++)` 里 **i 是 uint8**，`i<260` 恒真 → 255 回绕到 0，**死循环**，CPU 卡死
- `EEPROM_Save(buf, 263)` 的长度参数是 **uint8**，263 被截成 7 → 从来没有真正保存成功过
- 串口命令帧缓冲只有 64 B，`0x22` 的 84 B 负载直接被丢弃

修完这三个，校准数据才真正掉电不丢。

### 结果

21 档全部实测写入后，用 1 kHz 基准复测：**1 ms 档 1000 Hz、1.5 ms 档 1000 Hz、2 ms 档 1012 Hz**，误差 ≤1.5%。
同时发现快档（100 µs/格）的真实采样间隔是标称的 2.2 倍——所以固件里把**时基标签改成显示实测值**，
屏幕上看到的就是真实时间轴，不再"骗人"。

> 说明：这套 STM32 基准校准流程是开发时的工具，不随固件发布；发布固件里已经包含了标定好的
> `CalTable` / `DtTbl` / `TK` / `WS` 等全部系数，存放在 EEPROM，设备上可直接微调。
